# Response conventions

- Every user-facing response must begin with a concise Markdown H4 title (`#### ...`) that dynamically summarizes the current response's content or task type. Do not place any visible text before the title. Titles such as `#### 复习`, `#### 英语学习`, `#### 习题讲解`, `#### 错题记录`, or `#### 规则维护` are examples only; do not treat them as fixed required wording.
- When any skill is used, including system, personal, or non-repository skills, the absolute final line of the response must be `*Generated by <skill-name> skill*`, replacing `<skill-name>` with the skill's actual name. Place one Markdown divider (`---`) immediately before the final attribution block.
- Do not add any text, punctuation, list marker, or other content after the skill attribution line.
- Put every standalone italic metadata or provenance line, including `*Picked from ...*`, only in the final attribution block. Do not place such lines in the title, teaching body, exercise body, or menu area.
- When a Git commit was created during the current turn, include exactly one visible commit notice: `*Committed -- <message>*`, replacing `<message>` with the exact commit message and adding no surrounding brackets. Do not also mention the same commit in the body text. Omit this line when no commit was created.
- Use exactly one Markdown divider immediately before the final attribution block. Inside that block, order the applicable standalone italic lines as provenance (`Picked from`) first, commit notice second, and skill attribution last, with no divider or blank line between them. If a skill attribution exists, it must remain the absolute final line; otherwise the commit notice is the final line when present.
- If any intended step did not actually execute, say so plainly in the body text before the final attribution block. Do not imply success for a skipped, failed, or blocked step.

# English learning menus

These rules apply to every skill and every user-facing response in this repository that actually teaches, explains, corrects, practices, or reviews English. They do not apply to repository maintenance, skill design, or other meta-level discussions merely because they mention English.

- End the teaching content with a numbered menu containing 3 to 5 concrete next-step learning options.
- Introduce the menu with `➡️ 接下来可以回复数字：`, and always place one Markdown divider (`---`) immediately before that menu intro line in every English learning response that shows a menu.
- Show the fixed Markdown H5 headings `##### Popular Menus` and `##### Other Menus` only when both groups contain at least one visible menu item. If either group would be empty, omit both group headings and list all visible menu items directly under `➡️ 接下来可以回复数字：`; do not display an empty group or write `无`. By default, put every visible option in the non-popular group. If the user has explicitly told you that specific stable menu intents belong in `Popular Menus`, place only those visible matching options in the popular group. Number every visible menu consecutively from 1 across the whole menu, including when the menu is split into `Popular Menus` and `Other Menus`; do not restart numbering inside `Other Menus`. Interpret later bare-number replies by this single continuous numbering.
- Review menus opened by `practice-learning-records` are the exception to the previous grouping rule: every review-related response that shows a menu must display `##### Popular Menus` and include at least one visible review-continuation or review-navigation option in that group. Place these visible stable intents under `Popular Menus`: `复习掌握不稳的知识点、语法和句型`, `综合复习低分知识点`, `继续复习，从复习库随机抽一道题`, `复习已标熟的知识点`, and `🔍 讲解当前习题`. Keep all other visible review options under `Other Menus`. Initial review-opening menus may omit the single focused `🧪 四六级规格习题` entry when they already include a distinct complete `📝 完整四六级套题（不含听力）` entry; follow-up learning, exercise, and review menus still include the focused `🧪 四六级规格习题` entry as usual.
- Give every menu item a different, semantically appropriate emoji. Do not reuse an emoji within the same menu.
- Always include a `🎭 场景对话` option tailored to the English currently being studied or reviewed. When no English target exists yet, offer a concrete everyday scenario that starts the dialogue practice directly. This option is mandatory in every English learning menu.
- Name the `🎭 场景对话` option from the current learning focus, not stale conversation history. Use “继续这段……” only when the immediately preceding user-facing turn was an active role-play dialogue and the current response is still continuing that same dialogue; after switching to explanation, comparison, correction, quiz, or production practice, relabel it as a fresh scenario for the current expression or rule.
- Always include a `🧪 四六级规格习题` option tailored to the English currently being studied or reviewed. This option is mandatory in every English learning menu and must be distinct from the scenario-dialogue option.
- Cover at least two activity types, such as grammar, vocabulary, comparison, pronunciation, translation, production, quiz, or scenario dialogue.
- Use specific descriptions such as `🎭 在机场问路的场景对话`; do not use vague labels such as “继续学习” or “了解更多”.
- If the current response has not substantially explained the grammar of the English being studied, make `🧩 获得这句话（或当前英语）的语法讲解` the first menu item. A substantial grammar explanation must cover at least one relevant point such as sentence structure, tense, clause structure, non-finite verbs, or scope of negation.
- If grammar has already been substantially explained, do not repeat the generic grammar-entry option; offer a more specific grammar exercise only when useful.
- When the user replies with one or more numbers from the latest menu, execute those options in order without asking them to resend the English. Then provide a new menu that follows these same rules.
- Do not interpret numbers inside ordinary English, exercise answers, or unrelated messages as menu selections.
- Number exercise questions with Arabic numerals (`1`, `2`, `3`, ...), never with `A`, `B`, `C`, and so on. Choice labels inside a question may still use `A` through `D` where required.
- The pre-menu divider is required even for pure explanations, answer evaluations, role-play turns, and menu-only responses; it visually separates the follow-up action area from the current teaching content.
- After the menu, place one divider and then the final attribution block. Put any `Picked from` provenance first, the commit notice second when present, and the skill attribution last, without blank lines between them. Do not place standalone italic metadata anywhere before the menu.

When the user selects the mandatory exercise option, generate one focused text-based task modeled on the official CET-4/CET-6 assessment rather than an entire paper:

- Label the task with its level and format, for example `CET-4 · 仔细阅读` or `CET-6 · 汉译英`.
- Default to CET-4 when the user's level is unclear. Use CET-6 when the source material or the user's demonstrated ability is clearly more advanced, and adapt future difficulty from the user's answers.
- Choose a format that fits the current knowledge point: contextual word-bank cloze, paragraph matching, careful-reading single choice, Chinese-to-English paragraph translation, or prompted short writing.
- Do not generate listening questions or simulate listening material.
- Preserve the tested expression or rule but place it in a new context; do not merely ask the user to repeat the original example.
- Do not reveal the target word, the correct option, or the correct answer in the exercise title, prompt, menu label, or any pre-answer hint. Use neutral wording such as `本题` or `当前知识点` when naming the task.
- For single-choice questions, provide one best answer and plausible distractors labeled `A` through `D`. For productive tasks, provide a clear prompt and proportionally shortened requirements suitable for one chat turn.
- Do not present isolated grammar trivia as an official CET question. Test grammar through vocabulary in context, reading, translation, or writing.
- Do not reveal the answer before the user responds. After the response, give a clear judgment, explain the decisive point, provide the correct or improved answer, and then append a new compliant menu.
- Both immediately after presenting the exercise and after evaluating the user's answer, the numbered menu must include the fixed option `🔍 讲解当前习题`. When the user selects it, explain the current exercise's text or prompt, tested knowledge, reasoning, and relevant answer choices or model answer; do not replace it with a new exercise.

Prefer these stable emoji meanings when they fit, while keeping every item in one menu visually distinct:

- `🧩`：语法讲解或语法训练。
- `📚`：词汇、短语或搭配。
- `🔄`：近义表达、句型或语气对比。
- `🎧`：发音和听力辨析。
- `✍️`：翻译、改写或造句。
- `🧪`：参照 CET-4/CET-6 规格的纯文本习题。
- `🎭`：带角色与背景的场景对话。

# Exercise and dialogue error recording

These rules apply to every skill that presents an English exercise and evaluates the user's answer, or runs an active English scenario dialogue and corrects the user's English response.

- Write an `errors` category record only when the user is answering an explicit exercise or participating in an active English scenario dialogue, and at least one submitted answer is judged incorrect or contains a concrete error that needs correction. Do not create an error record from ordinary English input, free conversation outside an active English-learning role-play, explanations, examples, unanswered questions, or fully correct exercise/dialogue answers.
- After explaining the error and giving the correct or improved answer, record each distinct reusable error pattern through `learn-from-english/scripts/learning_records.py`. When the same response also scores a reviewed knowledge point, include every demonstrated error in one `complete-review` transaction; for an unscored scenario dialogue, use one `batch-upsert` transaction. Never edit `learning-records/records.json` directly.
- Use a stable semantic `--key` that describes the error pattern rather than the exercise, date, or conversation. Use the user's incorrect answer as `--source`, and put a corrected representative sentence in `--example`.
- Error recording is independent of the active skill and independent of review scoring. When a review exercise tests an existing record, update that record's score and save every newly demonstrated error pattern in the same `complete-review` transaction. Scenario dialogue corrections do not by themselves trigger review scoring unless the dialogue is explicitly being used as a scored review task.
- Record only errors actually demonstrated in the submitted answer. Do not infer or invent additional weaknesses, and do not record an error merely because the overall score is below a threshold.

# Commit conventions

- After any repository content is added, modified, moved, or deleted, automatically create a Git commit for those changes before finishing the current turn.
- When committing, stage only the changes made for the current task. Do not include unrelated user changes.
- Use `[records]: xxx` when the commit changes only the canonical `learning-records/` data.
- Use `[skill]: xxx` when the commit changes only skill files.
- Use `[readme-doc]: xxx` when the commit changes only `README.md`.
- Use `[agents-doc]: xxx` when the commit changes only `AGENTS.md`.
- Use `[refactor]: xxx` when the commit mixes more than one of the content types above.
- In every format, replace `xxx` with a concise description of the changes.
