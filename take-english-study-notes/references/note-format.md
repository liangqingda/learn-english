# 复习笔记格式与写入规则

本文件是 `learning-record-notes/` 笔记的**唯一规则来源**；`SKILL.md`、`README.md`、`learning-record-notes/README.md`
只做指引，不再复述细则。版式本身以 `take-english-study-notes/templates/review-note.md` 为准，校验规则由
`take-english-study-notes/scripts/check_note.py` 强制执行。三处冲突时按「模板 → 校验器 → 本文件」的顺序取用。

## 何时写、写到哪

- 复习 / 练习 / 套题笔记只在用户已经提交答案、且评分与错题保存成功（或用户明确放弃保存）之后写；未作答的题组、
  纯菜单、`stats` / `history` / `paper-get` 查询、`next-review` 领取阶段都不写文件。
- 讲解笔记由 `learn-from-english` 在首次讲解后写：本轮实质讲解的每条记录各写一份，用 `note.py explain` 创建。
  讲解是**文件级固定小节** `## 讲解`，紧跟 `## 基础信息` 表格之后、位于所有日期区块之前：一个知识点只有一次首次讲解，
  复习才会多轮，所以讲解不参与轮次编号；之后这条记录的每次复习继续用 `note.py append` 把新日期区块插到同一个文件最前
  （`append` 会按记录 ID 自动定位已存在的文件）。
  一份笔记只有一份 `## 讲解`；文件已存在讲解时 `explain` 返回 `duplicate: true`，不要写第二份。
- 保存失败时只在当前对话保留内容，不落盘；用户明确放弃保存后仍写笔记，但追踪字段标注「评分未保存（已放弃）」。
- 一轮复习只写一个文件；分段提交答案时只在最终评分结束时写一次完整版本。套题按整套写一个文件，不按 Part 拆分。
- 同一个记录反复复习会**持续改写同一个文件**：每轮在最前插入一个日期区块（最新一轮在最上，旧区块依次后移），同一轮内的修改（补错题讲解、补场景对话原文、追加菜单项）用 `replace` 就地替换该区块。
  因此区块内同时保留两个时间：`笔记生成时间` 只记首次写入，`笔记更新时间` 记该区块最后一次修改，两者相同时说明写过之后没再改。
- **讲解型内容一律进文件级讲解区，日期区块只放习题**：菜单项里只有「讲解要点 / 对比 / 场景对话 / 小故事」这类内容时，写成
  `## 讲解` 之后的文件级小节；只有该菜单项**带习题**时，才在日期区块里另建一个同名小节并只写习题（题号、题目、答案、判定、讲解折叠块）。
  同一条记录的讲解要点只在第一轮写一次，后续重复选择只往日期区块写习题，不再改动讲解区。
  同一个菜单项被重复选中时，除场景对话与小故事外不再重复记录（例如「对比相近表达」记录过一次后，后续不再新建小节）。
- 场景对话与小故事是例外：每选中一次就要追加一段完整原文，第二段起按 `场景对话原文 1 / 2`、`故事原文 1 / 2` 编号。
- 只要本轮有习题，就按 0 至 10 分给出得分，题量与错题数一并记录。复习与套题把得分写进规范记录；
  `follow-up-learning` 练习、`error-clusters` 专题练习、互动角色扮演里用户实际作答的题组同样计分，
  但得分只写进笔记（`本轮得分` 填 `x / 10`、`分类 · 状态变化` 填 `<category> · 未入库`），不调用 `complete-review`。
  纯展示项（场景对话脚本、小故事、讲解）不产生题组，也就没有本轮得分。
- 笔记按分类分目录存放：`learning-record-notes/<category>/<category>-<slug>.md`，目录名必须等于文件名前缀
  （`errors/errors-out-west.md`、`paper/paper-cet6-xxx.md`）。目录与文件名前缀不一致、或直接放在
  `learning-record-notes/` 根下都会被校验器拒绝；`categories.json` 与 `README.md` 留在根目录。
- 文件名不带日期：`learning-record-notes/<category>/<category>-<slug>.md`。`category` 只能取 `learning-record-notes/categories.json`
  里声明的键（现有 `vocabulary`、`phrases`、`grammar`、`usage`、`errors`；套题用 `paper`）；一轮练习即使实质考查 ≥2 个分类，
  也只写「锚点记录」所在的分类——锚点取本轮错得最多、
  或主要考查的那一条记录，它的记录 ID 就决定文件名；禁止 `mixed`、`misc`、`practice` 等自造前缀。
  写入命令仍接受旧式平铺路径（`learning-record-notes/<category>-<slug>.md`）：`NoteStore.resolve`
  会按文件名前缀算出分类目录，并在第一次写入时把旧文件移进去。
- **分类清单只有一份**：键、中文标题、展示顺序与 `hidden` 都由 `learning-record-notes/categories.json` 定义。
  改标题、调列顺序、把某类从看板藏起来只改这个文件，不要再抄一份到笔记正文、复习菜单或其他项目
  （`my-dashboard` 的英语页直接读它来排看板列）。**新增一个全新分类**除了改该文件，还要新建同名目录
  （`learning-record-notes/<new-key>/`）、同步本节的
  分类列表、`check_note.py` 的分类集合和下面的「各分类必写栏」——校验器靠那里拦自造前缀。
  别处读到的不在清单里的前缀，说明这里是唯一漏改的地方。
- `slug` 取记录 `id` 或 `paper_id` 的语义部分，只保留小写字母、数字、连字符。记录 `key` 与 `slug`
  一律用 ASCII，中文主题必须意译成英文短语（`usage:after-不宜直接当-later-连接后续动作`
  应写成 `usage:after-vs-later-sequence`），不得把中文直接拼进 `key`；`learning_records.py` 会把
  非 ASCII 字符压掉而报 key 无效，`check_note.py` 也会拒收中文文件名。
  校验器要求 `<category>-<slug>.md` 与「记录 ID / 试卷 ID」逐字一致：`errors:back-west-spacing` 必须写在
  `errors-back-west-spacing.md`。
- 主题相同就复用同一文件：只要本轮焦点与既有文件的记录 ID 或 slug 主题相同、互为包含关系，就必须追加到该文件，
  不得按日期、轮次或「换了一种练法」另建新文件。
- 记录移动到 `mastered-learning-records/` 后 `id` 不变，继续写同一个文件；只有记录 ID 真正变化时才另建文件。
- 区块标题用 `date '+%Y-%m-%d %H:%M'` 取本轮结束时的本地时间。
- 笔记里不写 `claim_owner`、`claim_token`、临时 payload 路径或其他会话内凭据。

## 追加与修正

笔记的**唯一**写入方式是脚本命令，禁止用 `Write` 改写笔记文件。统一入口是本 skill 自带的
`take-english-study-notes/scripts/note.py`：写入由本 skill 的 `note_store.py` 完成（排他锁 + 原子替换），校验由同目录的
`check_note.py` 完成，不需要装其他 skill 就能写。唯一跨 skill 依赖是只读的记录事实：追踪表比对通过
`learning_records.py record-tracking --id <id>` 取回期望值（先看 `$LEARN_ENGLISH_CLI`，再看仓库内同级目录与安装位），
取不到时返回 `tracking_skipped`，不阻断写入。

1. 用 heredoc 把本轮区块通过标准输入传给命令，**不要**先写固定路径的临时文件（如 `/tmp/note-block.md`）；
   确需文件时用 `mktemp`。区块第一行必须是 `# <YYYY-MM-DD HH:MM> · <复习|练习|套题>`，一个区块只能有一个标题行。
   `· 讲解` 不是合法区块：讲解写文件级 `## 讲解` 小节（见下一条）。
2. 追加：
   ```bash
   python3 take-english-study-notes/scripts/note.py append \
     --file learning-record-notes/<category>/<category>-<slug>.md \
     --content-file - --check <<'EOF'
   # <YYYY-MM-DD HH:MM> · 复习
   …本轮区块全文…
   EOF
   ```
3. 命令在 `learning-record-notes/.notes.lock` 上取排他锁，锁内完成「读现有文件 → 把本轮区块插到 `## 讲解` 之后、所有旧区块之前并补 `---` 分隔 → 原子替换」。
4. 返回值语义：
   - `appended: true, heading_adjusted: false`：正常写入。
   - `appended: true, heading_adjusted: true`：这一分钟已被另一轮占用，或直接写入会打乱最新在前的顺序，
     **本轮已用顺延后的分钟保存**，`heading` 是实际写入的标题，`requested_heading` 是原请求；
     两轮内容都保留，按 `heading` 继续后续修正。
   - `appended: false, duplicate: true`：该标题的**同样内容**已存在（重试或并发冲突的产物），按已写入处理，
     不要重试、不要手工补写。
5. 追加菜单小节：**先判断这一项属于讲解区还是日期区块**（见「何时写、写到哪」）：
   - 讲解型（讲解要点、对比、场景对话、小故事）：用**文件级小节**命令，锁内把这一节插到 `## 讲解` 之后、所有日期区块之前。
     ```bash
     python3 take-english-study-notes/scripts/note.py append-explain-section \
       --file learning-record-notes/<category>/<category>-<slug>.md \
       --content-file - --check <<'EOF'
     ## <菜单项原文>
     **讲解要点**：
     - …
     EOF
     ```
     - 内容必须以 `## ` 开头、不能含一级标题；`appended_section: true` 表示已写入。
       `note.py sections --file <笔记>` 的 `explain_sections` 列出讲解区已有标题，写之前先看它就知道这一项是否已记录过。
       讲解要点要改、要补，都用同一个命令加 `--rewrite` 就地整节替换该小节（别的小节与日期区块不动），
       不要新建同名小节绕过去。这条规则对三类文件级小节一视同仁：带习题菜单项的 `**讲解要点**`、
       场景对话小节（要点 + `场景对话原文` 折叠块）、小故事小节（要点 + `故事原文` + 收尾三列表）。
       `--rewrite` 是整节替换，原有的场景对话 / 故事原文必须一并带上，漏掉已有原文的重写会被直接拒绝；
       只是再多一段原文时仍用 `append-explain-part` 追加，不做整节重写。
     - `duplicate: true`（同标题小节已存在）：说明这一项已经记录过，**不要按新内容再记录第二次**（返回里带同样的 `hint`）；
       确需修正或补充讲解要点时，改用上面那条 `--rewrite`。
     - 同一个菜单项第二次出场景对话 / 小故事时，用 `append-explain-part` 往同一小节末尾追加一段原文：
       命令会自动把第一段的 summary 改成 `<base> 1`，其余按顺序编号。
     ```bash
     python3 take-english-study-notes/scripts/note.py append-explain-part \
       --file learning-record-notes/<category>/<category>-<slug>.md \
       --section "## <文件级小节标题>" --content-file - --check <<'EOF'
     <details>
     <summary>场景对话原文 2</summary>
     …
     </details>
     EOF
     ```
   - 带习题的菜单项：日期区块里用**追加小节**命令，锁内只把这一节塞进既有区块，区块其余内容一字不动；
     **不要**为了加一节而整块 `replace`。小节内只写 `### <n>. <题型>` 习题，不重复 `**讲解要点**：`。
     ```bash
     python3 take-english-study-notes/scripts/note.py append-section \
       --file learning-record-notes/<category>/<category>-<slug>.md \
       --heading "# <目标区块标题>" \
       --content-file - --check <<'EOF'
     ## <菜单项原文>
     ### 1. <题型>
     …
     EOF
     ```
     - 内容必须以 `## ` 开头、不能含一级标题；目标标题必须与文件里已有区块完全一致。
     - `appended_section: true`：已追加。`duplicate: true`：同一标题同一内容已经在区块里，按已写入处理，不要重试。
     - 报 `section … already exists in this block` 时说明同标题小节已存在且内容不同：改用 `replace` 修正整块，
       不要追加第二个同标题小节。
6. 本轮区块刚写错时才用替换命令（同样走 stdin，标题行必须与追加时返回的 `heading` 完全一致）；
   写入命令会自动把 `笔记更新时间` 刷成本次写入的分钟（追加、区块替换、追加小节都算），不要手工改这一行：
   ```bash
   python3 take-english-study-notes/scripts/note.py replace \
     --file learning-record-notes/<category>/<category>-<slug>.md \
     --heading "# <本轮标题>" \
     --content-file - --check <<'EOF'
   # <本轮标题>
   …修正后的本轮区块全文…
   EOF
   ```
   替换是整块覆盖，但命令在锁内做了兜底：凡是新内容没有带上、而文件里已经存在的 `## ` 小节，都会被原样保留在
   区块末尾，并在返回值 `preserved_sections` 里列出（这些是别的对话的成果，不要手工删）。只有用
   `--drop-section "## <小节标题>"`（可重复）显式列出的小节才允许真的删除。
   替换一次只允许改**一个**小结：新内容同时改了两个及以上既有小节时命令直接拒绝（避免范围写宽的替换吃掉整段内容），批量迁移要对每个小节逐个加 `--rewrite-section "## <小节标题>"`，返回值 `modified_sections` 列出实际被改写的小节。
   只改一个日期区块，其他日期区块原样保留；不要在标题重复或指向不明时替换。
   改小节正文时必须用锚点收边（下一个 `##` / `###` / `</details>`），并核对 `<details>` / `</details>` 成对、原有小节一个没少；写完同一轮跑 `check --all`。

7. 讲解笔记用讲解命令创建（只有 `基础信息 + ## 讲解`，没有日期区块；后续复习再 `append` 追加）：
   ```bash
   python3 take-english-study-notes/scripts/note.py explain      --file learning-record-notes/<category>/<category>-<slug>.md      --content-file - --check <<'EOF'
   ## 基础信息
   …追踪表…
   ## 讲解
   **英文原文**：…
   EOF
   ```
   - 内容必须含 `## 基础信息` 与 `## 讲解`，且不得含任何一级（日期）标题，否则直接拒绝。
   - `appended: true`：创建成功。`duplicate: true`：该文件已有 `## 讲解`，按已写入处理，不要重试。
   - 文件已存在但没有 `## 讲解` 时不要改用 `append` 或 `Write` 补：加 `--update` 再跑一次，命令会把这一节插到
     `## 基础信息` 表之后、所有日期区块之前（返回 `inserted: true`），已有内容一字不动。
   - 讲解正文暂时没内容时写占位提示，但仍须满足讲解版式：至少两栏 `**<栏目>**：`，其中一栏是本分类必写栏
     （`vocabulary`/`phrases` → `核心含义`、`grammar` → `语法机制`、`usage` → `语气与语域`、`errors` → `错误机制`），
     每栏下面至少一条列表项；不要留空的 `## 讲解`，也不要写成一句散文。占位提示固定写法：
     ```markdown
     **<本分类必写栏>**：
     - 本条为历史知识点补建笔记：建笔记时还没有生成过讲解，正文留空待补。

     **待补充**：
     - 下次讲解或复习这条知识点时，按本记录的分类补写本节；补全后用 `note.py explain --update` 替换这段占位内容。
     ```
   - 每份笔记都必须有 `## 讲解`。任何写笔记的 skill 在 `append` / `append-explain-section` / `append-explain-part` / `append-section` / `append-part` / `replace` 之前先确认它存在，
     缺了就先按上一条补（没有正文就写占位），再写本轮区块。校验器允许缺讲解，所以这只能靠写入路径保证。
   - 该记录若已存在于其他笔记文件，命令拒绝另建新文件并给出应复用的路径。
8. 新建文件同样走追加命令：第一个区块**必须**在标题行之前带上 `## 基础信息` 与追踪表，命令会把它写到文件最顶部；
   写入已有文件时同一次调用里多带的 `## 基础信息` 会被自动忽略，不会重复落地。缺这一段时创建新文件会被直接拒绝。
   文件里已有 `## 讲解` 时，本轮区块插在整个文件级讲解区（`## 讲解` 与只讲解的菜单小节）之后；若文件已有日期区块，本轮与旧区块之间写一行 `---`。
9. 只修顶部 `累计复习次数` / `下次复习` 两行（记录级字段）用同步命令，不要用 `replace` 去改整个区块：
   ```bash
   python3 take-english-study-notes/scripts/note.py sync --file learning-record-notes/<category>/<category>-<slug>.md [--check]
   ```
   - 值来自 `record-tracking`，只改「基础信息」表里的这两行，日期区块里的同名行一个字都不动，返回 `synced`。
   - `append` / `replace` 写完后也会自动回填这两行（`basic_info_synced`），所以日常复习不需要额外跑这一条；
     它用于修复历史笔记，或另一条记录改了复习计划后笔记顶部停在旧值的情况。
   - 记录库不可用时返回 `tracking_skipped`，不阻断操作。
10. `--check` 的结果在返回 JSON 的 `check` 字段，同时给出 `check_ok` 与 `note_status`：
   - `note_status: "valid"`：笔记合规。
   - `note_status: "invalid"`：写入已成功但笔记不合规（进程退出码 1）。按 issue 的 `line` / `message` 用替换命令就地修正，
     再重跑一次；**不要**把退出码 1 当成写入失败去重试追加。
   - `note_status: "unverified"`：校验器不可用，未执行校验；在回复里如实说明「本轮笔记未校验」，不要当作通过。

## 模板结构

唯一格式来源是 `take-english-study-notes/templates/review-note.md`：只允许替换 `<…>` 占位符，
不得新增、删除、重排任何标题、字段、空行、列表符号或标记，也不得自创 `## 追踪` 这类错层标题。
文件最顶部放**全文件唯一一份**的 `## 基础信息` 二级标题（用作导航）与紧随其后的追踪表，承载与单次复习无关的记录级字段；
每个日期标题下先写 `## 本轮习题`，本轮追踪表紧跟在该标题之下、第一题之前（表格本身**不加小标题**），
带习题的菜单项小节同样在自己的标题下先写两行表（`本轮得分` / `题量与错题数`），再写第一题；只记这一轮发生过什么。基础信息与讲解两处都**固定展示、不折叠**，不要写 `<details>`。

固定骨架：

| 层级 | 固定写法 |
|---|---|
| 文件开头 | 先写 `## 基础信息` 二级标题与追踪表（整个文件唯一一份）；讲解笔记接着写 `## 讲解`，需要时再写只讲解、不带习题的菜单小节；之后才是第一个 `# <YYYY-MM-DD HH:MM> · 复习` 区块（kind 换成 `练习` 或 `套题`）；全文件只有日期这一类一级标题 |
| 轮次区块 | `# <YYYY-MM-DD HH:MM> · <复习 / 练习 / 套题 之一>`；两个以上区块之间必须有一行 `---`，文件末尾不写分隔符；区块按时间倒序排列（最新一轮在最前，旧区块依次在后），一轮一个标题 |
| 讲解小节 | `## 讲解` 是整个文件唯一一份、固定展示（不折叠）、必须位于基础信息表之后与所有日期区块之前；只写讲解正文，不写 `讲解时间` / `分类 · 状态变化` / `本轮得分` / `题量与错题数` 等本轮字段，也不写 `## 本轮习题` |
| 讲解正文 | 用 `**<栏目>**：` 分栏，**栏目按本记录的分类选取、不固定、不要求凑齐**：一份笔记只讲自己这一层，跨分类的内容留在对应分类的文件里；至少两栏，每栏内容写成列表或表格，标签后不留空 |
| 各分类必写栏 | `phrases` → `**核心含义**：`；`grammar` → `**语法机制**：`；`usage` → `**语气与语域**：`；`vocabulary` → `**核心含义**：`；`errors` → `**错误机制**：`（校验器按文件名分类核对，缺这一栏直接报错） |
| 各分类建议栏 | `phrases`：核心含义 / 使用场景与语气 / 结构与搭配 / 历史文化背景 / 发音 / 容易混淆 / 可迁移表达；`grammar`：语法机制 / 结构拆解 / 与相近结构对照 / 常见误用 / 可迁移句型（**不写历史文化背景与发音**，对语法没有解释力）；`usage`：核心含义 / 语气与语域 / 使用场景 / 历史文化背景 / 容易混淆 / 可迁移表达；`vocabulary`：核心含义 / 搭配 / 近义辨析 / 历史文化背景 / 发音 / 可迁移表达；`errors`：错误机制 / 为什么错 / 正确表达 / 可迁移表达 |
| 基础信息区 | 文件最顶部、**整个文件唯一一份**、固定展示：`## 基础信息` → 空行 → `<table style="border-collapse:collapse;width:auto">` → `<colgroup><col width="150"><col></colgroup>` → 6 行 → `</table>`，之后空一行接第一个日期标题；不要包进 `<details>` |
| 基础信息字段顺序 | 记录 ID / 试卷 ID → 目标知识点 → 累计复习次数 → 下次复习 → 笔记生成时间 → 笔记更新时间（全部是与单次复习无关的记录级字段） |
| 本轮信息区 | 日期标题下**先写 `## 本轮习题`**，再在其下写追踪表；表格位于该标题与第一题之间，不折叠、不加小标题 |
| 本轮信息表 | 写在本轮信息区、不写表头：`<table style="border-collapse:collapse;width:auto">` → `<colgroup><col width="150"><col></colgroup>` → 4 行 `<tr><td>字段</td><td>值</td></tr>`（套题 5 行） → `</table>` |
| 本轮字段顺序 | 复习时间 → 分类 · 状态变化 → 本轮得分 → 题量与错题数；**`主观题得分` 只属于套题**，紧跟「题量与错题数」之后，「复习 / 练习」不得写这一行 |
| 复习时间 | `YYYY-MM-DD HH:MM`，必须与轮次标题的时间完全一致（标题写 `# 2026-11-08 21:00 · 复习`，本行就写 `2026-11-08 21:00`） |
| 习题区 | `## 本轮习题` 是复习 / 练习 / 套题区块内第一个二级标题，其下先放本轮信息表，再每题一个 `### <n>. <题型>`，题号从 `1` 连续递增；讲解小节不写习题区。纯练习轮次（kind 为 `练习`）的题目按菜单项分节写，`## 本轮习题` 可以只带本轮信息表、下面不留题目，但整个区块至少要有一道题（校验器按 kind 判断） |
| 每题字段 | 依次 `**题目**：` → `**我的答案**：` → `**判定**：`，字段之间空一行 |
| 题内编号 | 选项、多个待判断句、要点手写编号时**顶格写** `1.`，不要写成 `- 1.` / `* 1.` / `- 1)`：Markdown 会把编号渲染成无序列表里再套一层有序列表，校验器会报错 |
| 判定标记 | 只允许 `✅ 正确`、`⚠️ 部分正确`、`❌ 错误`、`⚠️ 未作答`，可在括号内补一句短说明 |
| 题型 | 只允许：单项选择 / 填空 / 改错 / 改写 / 翻译 / 语境判断 / 造句 / 短写作 / 综合运用 |
| 知识点折叠块 | **每道题都必须有**（套题可按 Passage/Part 合并，见「内容要求」），且必须是本题第一个折叠块：`<details>` + `<summary>知识点讲解</summary>`；块内固定四步 `1. **本题知识点**：` `2. **规则与机制**：` `3. **英语的表达逻辑**：` `4. **可迁移表达**：`；答对的题同样要写 |
| 错题折叠块 | 判定位含错误或未作答的题，在知识点讲解之后再写 `<details>`，summary 写 `错题讲解`；同一题多处错误时按序写 `错题讲解 1`、`错题讲解 2`…；块内固定四步 `1. **考点**：` `2. **为什么错**：` `3. **英语的表达逻辑**：` `4. **正确表达**：` |
| 未作答的错题块 | `⚠️ 未作答` 的题同样写 `错题讲解` 块，第 2 步标签换成 `2. **为什么答不出**：` |
| 菜单项讲解区（文件级） | 只有讲解、不带习题的菜单项，以及带习题菜单项的 `**讲解要点**：`，一律写在 `## 讲解` 之后、所有日期区块之前，以 `## <用户选中的菜单项原文，去掉 emoji>` 作二级标题（与 `## 讲解` 同级）；其下只写**一组** `**讲解要点**：`：每行一条要点，每条要点下面用两个空格缩进的子项写支撑它的**一个或多个可迁移表达 / 例句 / demo**，每句英文后附中文翻译（`  - I joined a studio after graduation.`（毕业后我加入了一家工作室））；不再另起 `**可迁移表达**：` 字段。写入用 `append-explain-section` |
| 日期区块内的菜单项 | 只有**带习题**的菜单项才在日期区块里建小节，标题与该菜单项的文件级小节同名；小节内**只写习题**（先写两行表 `本轮得分` / `题量与错题数`，再写 `### <n>. <题型>`、题目、我的答案、判定、知识点讲解 / 错题讲解折叠块），不再重复 `**讲解要点**：`。写入用 `append-section`，不要为加一节整块 `replace`；同一菜单项再选一次只追加新习题，不追讲解 |
| 菜单项重复选择 | 讲解只写首轮一次：同一菜单项被选第二遍时不再改动文件级小节，只在日期区块补这一轮的习题。场景对话与小故事例外：每次都要追加完整原文，用 `append-explain-part` 追加到同一小节末尾，第二段起编号为 `场景对话原文 1 / 2`、`故事原文 1 / 2`；不带习题的对比类小节记录过一次后不再记录 |
| 同一天多次练同一菜单项 | 日期标题**不变**（仍是 `# <YYYY-MM-DD HH:MM> · <复习 / 练习 / 套题>`，不加后缀）；同一天落在多个区块里时，这些区块算同一个「天组」，同一菜单项的习题小节从第 2 份起统一编号：最早那份 `## <选项原文> - 01`、下一份 ` - 02`……按时间升序连续；当天只有一份时**不加后缀**。写入命令（`append` / `append-section`）自动补号并把已有那份改成 ` - 01`，跨天各自从「不带后缀」重新起算；校验器核对单份不得带后缀、多份必须 ` - 01` 起连续，`--fix` 能自动补 / 去后缀 |
| 菜单项折叠块 | 只有一份原文时 summary 写 `<summary>场景对话原文</summary>` / `<summary>故事原文</summary>`，**不要编号**，也不要在块前写 `**完整场景对话**：`、`**故事原文**：` 这类标签行；同一小节出现第二份原文起，第一份改成 `场景对话原文 1` / `故事原文 1`，其余按出现顺序 `2`、`3`… 连续编号。`scenario-dialogue` 每块至少 4 句台词；`focus-story` 每块保留完整英文叙事（至少 8 句）且每个英文段落后面紧跟一行中文译文，块外保留收尾三列表（`故事里的位置` / `当时想表达什么` / `为什么不换别的表达`），多段故事每段各带一张表 |

## 追踪字段取值

### 文件级「基础信息」

| 字段 | 允许的写法 |
|---|---|
| 记录 ID / 试卷 ID | `<category>:<key>` 或试卷 `paper_id`；须与文件名一致 |
| 目标知识点 | 记录 `title` |
| 累计复习次数 | 数字，未评分 `—` |
| 下次复习 | `YYYY-MM-DD HH:MM`，未知 `—` |
| 笔记生成时间 | `YYYY-MM-DD HH:MM`；文件第一次写入的时间，之后不再变 |
| 笔记更新时间 | `YYYY-MM-DD HH:MM`；每次追加或替换后改成本次操作分钟，必须不早于 `笔记生成时间` |

`累计复习次数` 与 `下次复习` 属于记录级字段，值由规范记录决定：写入命令在 `append` / `replace` / `sync --check`
之后用 `learning_records.py record-tracking --id <id>` 取回期望值，把它们自动回填成记录的值（返回 `basic_info_synced`），
不需要也不允许调用方手抄。`append` / `replace` 只落日期区块，不会顺带改这张表，所以已有笔记的旧值要么等下一次写入自动纠正，
要么直接用 `note.py sync --file <笔记文件>` 就地修复。身份行（记录 ID / 目标知识点）与其余本轮字段不由同步覆盖，
不一致仍然返回 `tracking_mismatch` / `tracking_expected`。

### 每轮「本轮信息」

讲解小节没有任何追踪字段：它属于记录级内容（一个知识点只有一次首次讲解），只有日期区块才写下面这些行。

| 字段 | 允许的写法 |
|---|---|
| 复习时间 | `YYYY-MM-DD HH:MM`，与该轮标题时间一致 |
| 分类 · 状态变化 | `<category> · <旧状态> → <新状态>`；没有写入规范记录的练习写 `<category> · 未入库`；纯展示、没有题组的轮次写 `<category> · 未评分` |
| 本轮得分 | `x / 10`、`xxx / 710（无听力模拟折算分）`、未评分 `—`；保存失败且已放弃写 `评分未保存（已放弃）` |
| 题量与错题数 | `N 题 / M 处错误`；有未作答时补 `（另有 K 题未作答）` |
| 主观题得分 | **仅套题写这一行**：`写作 x/15 · 翻译 x/15`；`复习` / `练习` 整行不写，校验器会按 kind 判断行数 |

### 每轮「菜单小节信息」

带习题的菜单项小节在自己的标题下写一张两行表（不加小标题、不折叠），字段固定：

| 字段 | 允许的写法 |
|---|---|
| 本轮得分 | `x / 10`，该小节题组的 0 至 10 分；这些练习只写笔记，不写规范记录 |
| 题量与错题数 | `N 题 / M 处错误`；有未作答时补 `（另有 K 题未作答）` |

这两行由校验器核对：`N` 必须等于该小节内实际题目数，`M` 必须等于该小节内实际写出的 `错题讲解` 块数
（判错、部分正确都算，**未作答 / 未完成 / 漏答 不算**），`K` 必须等于该小节实际判为未作答的题数。
历史小节没有这两行时校验器不拦（当时没有计分口径），新写入必须带上。

`题量与错题数` 由校验器核对：`N` 必须等于 `## 本轮习题` 内实际题目数，`M` 必须等于实际写出的 `错题讲解` 块数
（判错、部分正确都算，**未作答 / 未完成 / 漏答 不算**），`K` 必须等于实际判为未作答的题数。
`M` 与写入 `errors` 的条数允许不同：属于目标知识点的错误计入扣分但不单独入库，独立错误才入 `errors`。

## 内容要求

- **版式必须渲染后分行**：选项、小题、多行答案一律用列表项（`- A. …`、`- (a) …`、`- (1) …`），
  禁止 `A. … B. … C. … D. …` 挤在同一段。
- `我的答案` 只写该题答案本身：去掉用户提交时的题号前缀与列表标记（`1. B`、`1) B`、`（1）B` 都记 `B`）；
  多题合并提交时按题号拆分，每道题只保留属于自己的内容，其余拼写和标点原样保留。不得为空，未作答写「不会」等实际回复。
- 每道题都必须写 `知识点讲解` 折叠块，可以超出当前复习知识点；答对的题也要写，不能因为正确就省略。
  唯一例外是套题按 Passage/Part 合并讲解：同一段阅读或同一个 Part 只由该段第一题写折叠块，其余题在该位置写一行
  `**知识点**：同第 <n> 题`（`n` 必须是本节内更早、且真的写了 `知识点讲解` 的题号），校验器会核对指向。
- 完全正确的题只写 `知识点讲解`；错题和带可复用错误的题在知识点讲解之后再写 `错题讲解`，只讲本轮实际出现并已讲解过的错误。
- 未作答题同样先写 `知识点讲解`，再写一个 `错题讲解` 块（第 2 步写 `为什么答不出`），给出参考表达与卡点机制；
  不允许只留一行「未作答」而没有讲解。
- 套题同样使用上面的固定骨架：每题一个 `### <n>. <题型>`（写作记 `短写作`、翻译记 `翻译`），不额外加 Part 小标题。
  **按 Passage/Part 合并 `知识点讲解`**：每段阅读只在段内第一题写完整四步折叠块，同段其余题写 `**知识点**：同第 <n> 题`
  指向它；写作与翻译各自独立写块。这样 57 题的套题不会膨胀成 57 份重复讲解。`主观题得分` 填
  `写作 x/15 · 翻译 x/15`，`本轮得分` 填 `xxx / 710（无听力模拟折算分）`。套题笔记因此会明显长于普通复习，
  这是规则要求的结果，不要为了控制篇幅删减知识点讲解。
- **所有内容都结构化记录，禁止整段文字**：分点的讲解、要点、规则、对比结论一律写成有序列表、无序列表或表格，
  一个子点一行；练习作答按习题区模板逐题展开，不要退化成只留「题号 / 题型 / 判定」的汇总表。
- **示范英文一律附中文翻译**：`## 讲解` 各栏的例句、`## <菜单项>` 里「讲解要点」子项的例句 / demo、折叠块里的
  `可迁移表达` 与 `正确表达`，英文句子后都要紧跟中文全角括号译文（`I joined a studio after graduation.`（毕业后我加入了一家工作室））；
  题型名、题目原句、选项、用户答案和 `home-cooked` 这类语言点名称本身不翻译。
- 这条只约束**新写入或本轮改写的区块**，不回溯改造历史笔记：旧笔记里的英文例句缺译文时照原样保留，
  不要为了套规则批量补译、重排或改动历史讲解。

## 菜单项写什么

用户在题组结束后通过数字菜单继续学习时，先判断这一项产出了什么，再决定写到哪里：

- **讲解型（不带习题）**：`follow-up-learning` 的语法/词汇扩展、`scenario-dialogue` 的场景对话、`focus-story` 的小故事、
  `error-clusters` 的专题讲解、对比相近表达等，写成 `## 讲解` 之后的文件级小节（`append-explain-section`），不进日期区块。
- **带习题的选择**：文件级小节只写 `**讲解要点**`（第一轮写一次），本轮实际作答的题目写进日期区块里同名的小节
  （`append-section`），格式与本轮习题完全一致：`### <n>. <题型>`、`**题目**`（必须完整抄写原题，含全部选项与小题）、
  `**我的答案**`（原样照抄）、`**判定**`、`知识点讲解` 折叠块（错题再加 `错题讲解`）。
- **重复选择**：除场景对话与小故事外，同一菜单项不再重复记录——`append-explain-section` 返回 `duplicate: true`
  就停手，不要改名绕过；后续只把这一轮的新习题追加到日期区块。
- `scenario-dialogue` / `focus-story` 每选中一次都要落一份完整原文：第一次写文件级小节，第二次起用
  `append-explain-part` 追加到同一小节；只有一份原文时 summary 写 `场景对话原文` / `故事原文`，出现第二份后
  改成 `场景对话原文 1 / 2`、`故事原文 1 / 2`，块前不写任何标签行。
- `focus-story` 小节每段故事：块内逐段写英文叙事、每段后紧跟一行中文译文，块外保留收尾三列表。
  只写讲解要点、不保留故事原文，等于这一段没有交付。
- 只记要点，不抄整段讲解原文；标题直接写用户选中的选项原文（去掉 emoji，不加编号和 `菜单：` 前缀）。
- **会切换题组的选项不记在本轮区块里**：`continue-review`、`review-path`、`familiar-review`、`mastered-review`、
  `explain-current-exercise`、`mastered-exam-paper`、`paper-history`、`continue-paper-attempt`、`retry-random-paper`
  开启的是新一轮，按新一轮自己的日期区块记录。
- 纯导航与查询（`status` 统计、重新打开菜单、`history`）不写。
- 本轮没有选择任何讲解型菜单项时，不追加菜单小节，也不要在习题后留空小节。

## 校验与历史迁移

写完必须校验通过。`--check` 已自动运行同一条命令，需要单独复查时运行：

```bash
python3 take-english-study-notes/scripts/note.py check --all          # 全量校验默认 notes 目录
python3 take-english-study-notes/scripts/note.py check --all --fix    # 先修无争议项再校验
python3 take-english-study-notes/scripts/note.py check learning-record-notes/<category>/<category>-<slug>.md
```

`--all` 用 `$LEARN_ENGLISH_REPO_ROOT`（缺省取本脚本所在仓库根）定位 `learning-record-notes/`，逐个分类子目录
（`errors/`、`phrases/`、`grammar/`、`usage/`、`vocabulary/`、`paper/`）收集 `.md`，跳过 `README.md`；
残留在目录根下的平铺笔记也会被收进来，并由校验器报「必须放进分类目录」；
CI 每次 push 跑这一条。`--fix` 只处理无争议问题：行尾空格、`我的答案` 的题号前缀、缺失的区块 `---` 分隔、
缺失的 `笔记更新时间` 行（按该区块 `笔记生成时间` 补齐）、把记录级字段上移到文件顶部唯一一份 `## 基础信息`、给每轮补 `复习时间` 行、把原先包住两处的 `<details>` 折叠块拆成固定展示（每轮表格不加小标题）、把日期标题下、`## 本轮习题` 之前的本轮追踪表移到该标题之下（内容一字不动）、删掉非套题里恒为 `—` 的 `主观题得分` 行，
删掉 `基础信息` 与第一个日期区块之间多余的 `---`、把旧版 `# … · 讲解` 轮次区块迁移为文件级 `## 讲解` 小节，
以及按当天的轮次给同名习题小节补 / 去 ` - 01`、` - 02` 序号、按真实习题小节重建隐藏锚点与文件级索引块，
不改题干、讲解、判定与区块顺序；它不需要人工触发——`append` / `replace --check` 发现校验失败时会自动修完再复检，
并用 `auto_fixed` 回传改了什么。追踪字段的身份值（记录 ID、目标知识点、状态变化、本轮得分、累计复习次数、下次复习）
同样由写入命令自动比对，不一致时返回 `tracking_mismatch` 与 `tracking_expected`。

校验器对**位置**是硬性规则：日期区块里出现 `**讲解要点**：` 或 `<summary>场景对话原文` / `<summary>故事原文` 折叠块，
一律报「日期区块只放习题」，写入命令（`append` / `replace` / `append-section` / `append-part`）也直接拒绝同样的内容。
这条规则只拦新写入与现存笔记：现存笔记已按规则迁移完毕，
所以 `check --all` 现在能在位置这一层兜住，不必再靠文档自觉。

同一天多次练同一菜单项时，**日期标题不变**，变的是习题小节标题：同一天的多个区块算一个「天组」，
同一菜单项的习题小节从第 2 份起按时间升序写成 `## <选项原文> - 01`、`## <选项原文> - 02`……
当天只有一份时不带后缀，跨天重新从「不带后缀」起算。`append` / `append-section` 会在锁内自动完成补号
（把已有那份改成 ` - 01`，新份写成 ` - 02`），返回值里 `section` 是实际写入的标题、`section_renamed` 列出被改名的旧标题；
手工写错时 `--fix` 会按轮次重排。`replace` 不改小节标题，修正带序号的既有小节时，
用 `sections` 返回的实际标题（含 ` - 01` / ` - 02`）去匹配，不要漏掉后缀。校验器对这条同样是硬性规则：单份带后缀、多份缺后缀或序号不连续都报错。

**可跳转索引（派生内容，由写入命令自动维护，不手写）**：每份带习题的菜单项小节，标题行**右侧**固定挂一个空元素锚点，
与标题同一行：`## 练习「a price to pay」的关键语法结构 <a id="practice-<YYYY-MM-DD>-<HHMM>-<8 位小写 hex>"></a>`。
它渲染时不可见，只在跳转时用，落在标题本身上；`hex` 取小节原文标题（去掉 ` - 01` 后缀）的 SHA-1 前 8 位，
所以同一天两份习题的锚点也不相同。文件级同名小节（`## 讲解` 之后的 `## <选项原文>`）的**讲解内容之后**再放一块索引，
前面单独一行写 `复习历史：`：

```
**讲解要点**：
- 名词 + 后置不定式用主动形式…

复习历史：
<!-- practice-index -->
- [2026-11-15 12:05 · 复习 - 02](#practice-2026-11-15-2100-8cd81652)
- [2026-11-15 12:05 · 复习 - 01](#practice-2026-11-15-1205-8cd81652)
<!-- /practice-index -->
```

条目按时间倒序列出全文件该菜单项的全部习题小节（新的在前），文本与日期区块标题同口径（`<日期> <HH:MM> · <复习|练习|套题>`），同一天同一菜单项有多份时按时间先后补 ` - 01`、` - 02`，
跳转目标取自真实小节。索引块固定落在小节的讲解内容之后、小节末尾，索引块后面不能再写讲解正文。

**复习目录（同类派生内容）**：`## 讲解` 的讲解内容之后同样写 `复习历史：` + `<!-- round-index -->` … `<!-- /round-index -->`，
按时间倒序列出整份笔记每个日期区块的 `## 本轮习题`（新的在前）；每个日期区块的 `## 本轮习题` 同样在标题行右侧挂
`<a id="round-<YYYY-MM-DD>-<HHMM>"></a>`，点一下就跳到那一轮的题目：

```
复习历史：
<!-- round-index -->
- [2026-11-15 12:05 · 复习](#round-2026-11-15-1205)
- [2026-11-07 20:22 · 复习](#round-2026-11-07-2022)
<!-- /round-index -->
```

一个区块固定一份 `## 本轮习题`，所以它的锚点只用日期与时间、无需标题哈希；同一天有两个区块时按时间先后写成
`2026-11-15 09:26 · 复习 - 01`、`2026-11-15 21:53 · 复习 - 02`，避免两行同名。

`note_store._write` 在每条写入路径之后统一重建两组锚点与两块索引，`check --all --fix` 也重建，因此改标题、增删习题小节或区块后
不需要手工同步；校验器逐条比对索引与真实小节、核对每个锚点存在且全文件唯一、锚点必须与所在区块和标题哈希一致，
并检查 `复习历史：` 这一行、索引块必须落在讲解内容之后，缺锚点、缺索引、缺标题、索引后还有正文、条目对不上或有残留索引块都报错。
只有文件级同名小节存在时才写习题索引块；该菜单项还没有任何习题小节时不留索引块；没有日期区块时也不留复习目录。
能不能点得动取决于渲染器：保留 HTML 属性的渲染器（GitHub、VS Code 预览）按 `#practice-…` / `#round-…` 跳到对应标题；
不支持 HTML 锚点的渲染器（Obsidian、Typora）只会显示成一行普通文字，纯文本视图同理——所以索引条目直接复用日期区块标题，
可读、跳不动时也能当目录看。

`ok: true` 表示笔记合规。`ok: false` 时按 issue 的 `line` 与 `message` 修正：

- issue 落在本轮刚追加的区块内：把修正后的完整区块交给同一把锁的替换命令就地替换，不要整文件重写、不要追加第二遍。
- issue 落在更早的历史区块内：不借本轮修改历史、不为通过校验重排旧区块；第二次仍不通过时，正常发送批改与讲解正文，
  并在正文里如实说明「本轮笔记未通过校验，已保留待修正」，把 issue 记在当前对话，下一轮优先修正该文件。

模板演进（新增/重命名折叠块、增加字段口径）导致历史笔记不再通过校验时，允许一次性迁移，但必须满足三条：
把新轮次插到最前、把历史日期区块按时间倒序重排（正文一字不改）、把折叠块拆成固定展示的裸表格、把记录级字段上移到文件顶部 `## 基础信息` 并给每轮补 `复习时间`、把旧版 `# … · 讲解` 区块改写成文件级 `## 讲解`（只搬正文、丢掉旧的讲解追踪行）、只补齐模板新增的追踪字段行（`笔记更新时间` 按相邻的
`笔记生成时间` 迁移）、或只删掉非套题里恒为 `—` 的 `主观题得分` 行；不得改动题干、`我的答案`、判定与正文讲解；日期区块只允许按时间倒序调整先后，内容一字不改；迁移前后用 `git diff`
确认没有正文删除。迁移不适用于日常整理。
