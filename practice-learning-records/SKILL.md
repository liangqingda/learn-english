# 复习英语学习记录

使用仓库根目录 `learning-records/` 与 `mastered-learning-records/` 中按 category 拆分的规范记录开展复习。`learning-records/<category>.json` 保存 `learning` 与 `familiar` 记录；同一知识点累计第 3 次达到 10 分后，写操作会把它移动到 `mastered-learning-records/<category>.json`。mastered 分类文件参考旧版 `mastered.json`，根节点直接是精简数组，每条保留稳定 `id`、`key`、`title`、`explanation`、`example`、`tags` 和 `mastered_at`。读取时工具会用 `explanation` 补 `source`，逐次评分历史和历史计数会重置；若记录此后失分回到 `learning`，`example` 与 `tags` 仍然可用，掌握前的逐次评分历史不会恢复。所有读取和写入必须通过 `learn-from-english/scripts/learning_records.py`；不得直接编辑 JSON。

## 打开复习菜单

收到触发词“你好”或“复习”（中文，去除首尾空白后仅为此二者），或单独的英文单词 review、hi（去除首尾空白后仅为此内容，忽略大小写）时运行：

```bash
python3 learn-from-english/scripts/learning_records.py menu --context initial
```

严格按返回的 `options` 顺序、`label` 原文和 `group` 展示菜单，不自行增加、删除、重新分组或估算数量。数量只保留在脚本生成的标签末尾。顶层选项跨分组连续编号为 `1`、`2`；option 含 `children` 时，在父项下把子项编号为 `1-1`、`1-2`，更深层继续追加段。把编号路径与 option 对象只保留在当前对话。脚本保证 `Other Menus` 至少动态生成 3 项；把 `mastered-exam-paper` 和返回的历史试卷选项原样放在 `Popular Menus`。把 `disabled: true` 的项显示为暂不可用但不执行；用户选择时说明记录正被其他会话领取并保持当前菜单。

若 `state` 为 `empty`，说明目前没有学习记录，并直接展示脚本返回的状态、基础练习和咖啡店场景入口，不编造历史知识点。

## 处理数字选择

只把对最近一轮菜单的纯数字或纯数字路径回复解释为菜单选择。始终根据 option 的 `kind` 分派，不根据 `label` 或 `id` 猜测行为；有 `action` 时按其中的 command 和参数调用 CLI，option ID 只用于稳定身份和父子关系：

- `review-path`：运行 action 指定的 `next-review --path <path>`。
- `continue-review`：运行 `next-review --random`。
- `familiar-review`：按 action 运行 `next-review --status familiar`。
- `mastered-review`：按 action 运行 `next-review --status mastered --random`，把它作为已掌握知识点的随机抽查。
- `mastered-exam-paper`：运行 `mastered-list`；用户已指定考试类型时使用相应 profile，未指定时根据当前学习目标选择合适类型并在卷首明确考试名称和评分规则。
- `paper-history`：只作为包含历史试卷 children 的导航父项，不直接执行。
- `historical-unanswered-paper`：按 action 运行 `paper-get --paper-id <paper_id>`，展示不含答案和解析的原卷；选择本身不创建作答。
- `continue-paper-attempt`：按 action 运行带 `paper_id` 和 `attempt_id` 的 `paper-get`，恢复已保存答案，只列出仍缺少的可作答项并继续该 attempt。
- `retry-random-paper`：运行 `paper-list --status completed --random`，再对返回的 `paper_id` 运行 `paper-get`；展示原卷但不展示旧答案，首次提交时省略 `attempt_id` 以创建新的 attempt。
- `starter-practice`：在没有学习记录时，围绕一个日常表达生成 2 至 3 道基础英语练习；不写入评分。题目未作答时不显示菜单；用户提交后批改，并仅在实际出错时用一次 `batch-upsert` 保存可复用错误。
- `scenario-dialogue`：有当前记录或 focus 时围绕它输出完整多轮场景对话；仅在两者都不存在时使用脚本给出的日常场景。不要把已有记录替换成咖啡店主题，也不要默认开启互动角色扮演，除非用户明确要求 role-play。
- `follow-up-learning`：围绕 option label 和 `focus` 生成语法、词汇、对比、发音或产出内容。若生成未作答练习，不显示菜单；用户提交后批改，但不调用 `complete-review`。只把实际展示的可复用错误用一次 `batch-upsert` 保存。若讲解引入新的稳定知识点，按“后续学习知识点记录”保存。
- `explain-current-exercise`：只在用户刚完成的复习答案存在错误或存在未作答题时解释该题组，不生成新题；错题说明考点、错误机制与正确表达，未作答题说明卡点与参考表达背后的英语计量、语义或结构逻辑。
- `error-clusters`：运行 `error-clusters`，按返回的 `options` 顺序与 `label` 原文展示（脚本已生成全部可选项，**禁止**再手工拼 `1-1` 子项、自行追加「未归类」入口或调整分组）。`tag_families` 只用来说明错题集中在哪类问题。
- `error-cluster-review`：用返回的 `cluster_id` 运行 `error-cluster-get --id <cluster_id>`，按取回的材料围绕该错误模式生成一组聚焦练习；明确这是未评分练习，不显示菜单，不调用 `complete-review`，也不批量修改成员记录。
- `error-cluster-review-unclustered`：运行 `error-cluster-get --unclustered --limit 8`，用取回的记录组成聚焦练习，其余规则同上。
- 上述两类练习在用户作答后，只把本次实际展示的新可复用错误用一次 `batch-upsert` 保存。
- `status`：执行返回的 action；初始进度入口通常运行 `stats --period 30d`，只请求分类数量时运行 `summary --include-familiar --include-mastered`。

上下文丢失或数字路径无效时重新运行初始菜单。不要要求用户重新发送“你好”，也不要尝试从规范学习记录恢复普通复习题组或待保存 payload；持久化套题必须通过 `paper-menu`、`paper-get` 和 attempt 数据恢复。

## 选择复习记录

脚本优先返回已经到期的记录，再综合 `next_review_at`、掌握分、遗忘次数和 ID 排序。没有到期记录时返回当前范围内优先级最高的记录。`--random` 只在优先范围中按低分和遗忘次数加权抽取。

执行任何 `next-review` action 前，先为当前对话生成不复用到其他对话的 owner 字符串，并追加 `--claim-owner <owner>`。命令会在写锁保护下写入短期 `review_claim`；保留返回的 owner 与 token，其他会话会跳过该记录。领取会自动过期，且不改变复习次数、分数或状态。

只在当前对话中保留题组、标准答案、作答进度、当前记录 ID、owner、token 和错误讲解状态；不要创建普通复习 session 文件。上下文仍在时继续当前题组；上下文丢失时明确说明不能恢复，并重新打开初始菜单，原领取等待自动过期。用户在评分前明确放弃或退出题组时运行 `release-claim --id <record id> --claim-owner <owner> --claim-token <token>`；释放失败时如实说明领取会等待过期。

“放弃保存”必须放弃当前复习事务的全部结果：评分、状态、复习次数、复习历史、下次复习时间、本轮新增或更新的 `errors`，以及 claim。只保留本轮开始前已经存在的未提交改动和其他任务产生的改动。`complete-review` 报错时，先以脚本的事务回滚结果为准；不得只释放 claim 就把本轮其他残留结果当作已放弃。

不得用 `git restore`、手工回退整份分类文件或其他宽范围操作实现放弃，因为这可能误伤本轮开始前的合法改动。若脚本报告回滚不完整，必须逐项确认本轮目标分类文件、`errors.json`、mastered 文件和 claim 的状态；在无法只撤销本轮结果时，明确说明仍有残留，停止生成正常菜单，并请求修复，不得声称“已放弃”。

命令返回 `record: null` 时明确说明当前范围没有记录，然后重新生成初始菜单；不得临时编造复习记录。

保留返回记录的 `id`、`category` 和 `status`，直到当前题组完成。新抽出记录并首次呈现题目时，直接输出题目本身，不在题目之前输出知识点标题、引导语或任何提示性内容（例如“本次复习的知识点是……”），避免作答前泄露答案方向；不输出菜单；不要在题目正文之前插入来源。仓库 AGENTS.md 要求的 H4 标题只使用不泄露知识点的泛化措辞（如“#### 复习题”）。把来源作为独立斜体元信息，放进题目之后的最终 attribution block：

```text
---
*Picked from <record-source> · <status> · <category>*
*Generated by practice-learning-records skill*
```

`learning` 与 `familiar` 的 `<record-source>` 使用 `learning-records`；`mastered` 使用 `mastered-learning-records`。来源行必须位于区块第一行；若本轮还有 commit notice，把它放在来源之后、skill attribution 之前。后续讲解或评价同一题组时不重复来源标注。

## 开展普通复习

根据记录设计 5 至 10 个短题，默认 6 题，按由易到难的顺序组织，并尽量参照四六级真题的命题风格，至少组合三种题型。`learning` 与 `familiar` 使用 `title`、`explanation`、`source` 和 `example`；`mastered` 的 source/example 是补齐值，只使用 `title` 与 `explanation` 并另造新语境：

- `errors`：使用新句子纠错或改写。
- `grammar`：组合造句、纠错、补全、语境选择或翻译。
- `vocabulary`、`phrases`：组合填空、搭配判断、释义辨析或造句。
- `usage`：组合语气辨析、自然度判断和场景表达。
- 可以适当加入选择题、填空题、改错题、改写题、翻译题、语境判断题和简短产出题，避免同一题型连续过多；题目应先易后难，前几题更聚焦识别和选择，后几题再逐步过渡到改写、翻译和综合运用。

题组必须考查同一知识点的多角度迁移，而不是反复改写同一个句子。出题前先拆出 2 至 4 个可迁移子点，例如搭配冗余、时间从句结构、语义边界、语域自然度、可替换表达或真实场景使用；每道题只聚焦其中 1 至 2 个子点。除非记录本身只有一个固定短语且无法迁移，否则同一题组必须满足：

- 至少 3 道题使用全新的语境、主语或动作，不沿用 `source` 或 `example` 的完整句子骨架。
- 仅当机制的成因确非显而易见、能真正考查理解深度时，才加入“为什么错/为什么自然”的机制判断题；对可直接套用规则（如基本比较级、固定搭配）的简单知识点，不要强行安排这种题，以免显得冗余。
- 至少 1 道题要求用户主动产出，如翻译、改写、造句或短场景回复。
- 至少 1 道题引入近义表达、相邻语境或干扰项，测试用户能否区分边界。
- 不要让 4 道及以上题目的标准答案都只是同一句核心英文的微小变体；如果题目读起来像同一道题换了编号，必须重写。

### 题组内的答案隔离

一套题必须靠语境复杂度、干扰项相似度和产出自由度区分难度，绝不能靠“别处已经写出答案”让题目变成填空题式送分。出题完成后先自检下面五条，任一条不满足就重写该题：

- **题干不得泄漏他题答案**：某题的题干、选项、括号说明或示例里，不得出现另一题的标准答案成分（尤其是介词、反身代词形式、固定搭配的后半截、被考查的语法形式）。例如前题考选 `Help yourself to ...`，后题题干又写出 `... to the fruit`，前题即失效。
- **选项不得共享被考成分**：四选一的干扰项必须是语义上真实可能、但在该语境下不成立的说法，不能是同一正确短语的残形（如 `Help yourself the sandwiches` 这种缺词拼法），否则用户不看题也能凭“只有一项拼得完整”猜对。
- **一题只考一个点，相邻题不得同点**：同一子点（某一介词、某一代词形式、某一固定搭配）只在一题中作为判断核心；其余题改用不同语境、不同产出方式再测同一知识点，不能用同一结构连问两遍。
- **识别题不给结构提示**：单选题若考场景识别，选项写成场景或意图描述，而不是若干只差一个词的句子，避免“句式全同、只挑一个完整版”。
- **至少两题是无提示产出**：用户必须自己决定用哪个表达、什么结构、单复数或语气，题面只给中文意图或场景，不出现目标表达的任何一个词。

要求用户按阿拉伯数字题号集中作答，作答前不公布答案。未作答题组是当前回复的唯一操作入口，不显示菜单。用户只回答部分题目时，确认已收到的题号并列出未答题号，不公布答案、不评分；用户补齐或明确跳过剩余题目后再综合评分。

不要根据文字回答评价实际发音。相邻两轮避免完全相同的题型组合。

## 后续学习知识点记录

`follow-up-learning` 不记录分数，但不是“只讲不存”。当后续学习内容引入当前记录之外的稳定、可复习知识点时，先讲解，再用 `upsert` 或一次 `batch-upsert` 写入学习记录：

```bash
python3 learn-from-english/scripts/learning_records.py batch-upsert --input <JSON 文件或 ->
```

输入格式：

```json
{
  "records": [
    {
      "category": "phrases",
      "key": "go-ahead-with-for-approved-plan",
      "title": "go ahead with：按计划推进",
      "explanation": "go ahead with + 名词表示获得允许或决定后继续推进某个计划、活动或安排，语气比 proceed with 更口语。",
      "source": "We can go ahead with the launch.",
      "example": "The team decided to go ahead with the launch.",
      "tags": ["follow-up-learning"]
    }
  ]
}
```

记录边界：

- 记录 `go ahead with`、`move on to`、`continue along` 这类新搭配，或一个新语法/用法差异。
- 不记录只是重复当前复习记录的规则、普通例句改写、临时练习题、完整示例对话台词、发音提示或用户尚未提交答案的题目。
- 若一次扩展讲到多个紧密相关的新知识点，合并为一次 `batch-upsert` 批量写入；每条记录使用稳定语义 `key`，选择 `vocabulary`、`phrases`、`grammar` 或 `usage`，不要为了普通新知识点使用 `errors`。
- 若脚本返回匹配到已有记录而不是新建，照常说明“已遇到/更新已有记录”；不要手工改 JSON。
- 写入失败时仍完成讲解，说明“本轮新知识点未能保存；本轮记录变更已回滚”，并把原始 payload 只保留在当前对话。不要显示正常菜单，只显示“重试保存”和“放弃保存并继续”；重试时原样提交，放弃时清除 payload。若回滚未完整成功，说明可能残留部分变更并停止后续写入。

## 讲解错题与未作答题

用户要求讲解刚才的错题或选择 `explain-current-exercise` 时，不要只说“不能说”“不自然”或重复规则标签。每道错题固定使用下面的模板输出，编号、加粗小标签、四步顺序都不得省略或合并。未作答题同样必须讲解：沿用同一四步结构，只把第 2 步标签换成 `为什么答不出`，写清卡在哪一步，并给出可直接背的参考表达。

````markdown
**错题 N：<用户答案或错误片段>（第 X 题）**

1. **考点**：本题实际考查的知识点。
2. **为什么错**：指出触发该判断的英语机制，例如可数/不可数的计量方式、冠词和量词的搭配条件、时态对应、词义边界、句子结构或语域限制。
3. **英语的表达逻辑**：说明英语把这个概念当作可数单位、不可数内容、动作过程、状态结果还是具体事件处理。
4. **正确表达**：给出正确答案，并附 1 至 3 个可迁移例句；中文直觉和英语分类不同时，明确对比。
````

未作答题的模板写法：

````markdown
**未作答题 N：<用户回复，例如“不会”>（第 X 题）**

1. **考点**：本题实际考查的知识点。
2. **为什么答不出**：这道题卡在哪一步，例如缺少可套用的框架、不会选动词、拿不准冠词，或根本没有产出思路。
3. **英语的表达逻辑**：说明英语把这个概念当作可数单位、动作过程、状态结果还是具体事件处理。
4. **正确表达**：给出参考表达，并附 1 至 3 个可迁移例句。
````

模板内各条仍须遵守：

- 选择题在模板之后逐项解释关键干扰项，再回到第 2、4 步的机制与正确表达。
- 改错或翻译题先说明用户原句想表达什么，再区分核心错误、自然度问题和可选风格改写。
- 避免把“规则名称”当作原因；规则名称后面必须跟一句可理解的机制解释。
- 翻译或整句产出类错题允许在四步之后追加一行“整句参考版本”，这是模板唯一允许的额外步骤；未作答题同样适用。
- 多道错题按题号顺序排列，每题之间空一行；模板用编号列表，不要改写成表格。表格只用于多题并列的得分与判定汇总。
- 错题、部分正确的题、未作答题以及用户明确跳过的题都要用模板讲解；未作答题给出参考表达，不把“没作答”当成无需讲解的理由。

## 评分与协调记录

用户完成一组可客观评价的复习后，逐题判断并给出自然答案，再综合评为 0 至 10 分：

- 9 至 10：完全正确且自然。
- 8：核心正确，有轻微问题。
- 5 至 7：部分掌握。
- 0 至 4：核心规则未掌握。

评分只衡量当前被复习记录对应的目标知识点是否掌握。执行时按下面顺序判断：

1. 先判断当前目标知识点本身是否答对。
2. 目标知识点答对时，必须按通过处理，不能因为答案里还有其他英语问题而把这个目标点判为未通过或降档。
3. 再检查答案里是否出现其他可复用英语错误；这些错误要单独写入本轮 `errors`。
4. 只有当某个错误本身就是当前目标知识点的一部分时，才把它计入当前知识点评分。

换句话说，主评分只看目标点是否掌握，附带错误只做独立记录，不互相覆盖。

在调用 `complete-review` 前必须执行一次「评分自检」，逐项核对全部通过后才允许写入：

1. 用一句话写出现行目标知识点，**以记录的 title（主规则）为唯一锚点**：explanation 中与 title 同一规则、支撑 title 的细则属于目标点；而 explanation 里标注为“更自然/更贴切/更口语”等次要自然度或语用偏好（例如某语境用某词更自然）**不构成目标点**，除非 title 本身就以该偏好为核心。拿不准时一律按 title 判定。
2. 逐题归因：把每道题及每个错误标记为「属于目标点」或「独立于目标点」。
3. 目标分数只由「属于目标点」的作答决定；任何「独立于目标点」的错误都只放入 `errors`，绝不降低目标分。
4. 只要答案里存在「独立于目标点」的错误，先确认它们已收录进本轮 `errors`，再提交评分。
5. 唯一允许把错误计入目标分的情形：该错误本身构成当前目标知识点的一部分。

若发现目标分曾因「独立于目标点」的错误被下调，必须先更正评分后再提交，不能把独立错误当作扣分依据。

把评分和本轮实际出现的可复用错误模式组成一个 JSON 对象，并只调用一次：

```bash
python3 learn-from-english/scripts/learning_records.py complete-review --input <JSON 文件或 ->
```

输入格式：

```json
{
  "id": "grammar:present-perfect-experience",
  "score": 7,
  "claim_owner": "<current conversation owner>",
  "claim_token": "<token returned by next-review>",
  "errors": [
    {
      "key": "stable-semantic-error-key",
      "title": "错误模式标题",
      "explanation": "纠错说明",
      "source": "用户的错误答案",
      "example": "修正后的代表句",
      "tags": ["review-error"]
    }
  ]
}
```

完全正确时传入空 `errors`。只记录用户实际展示并已解释的错误，不推断其他弱点。整个命令先校验评分和所有错误，再在本机写锁保护下逐个原子替换受影响的分类文件：任一输入无效时不会开始写入；跨文件写入中途失败时会尽力回滚本轮已替换的文件，但这不是单次文件系统事务。

一次成功的 `complete-review` 可能同时修改当前目标所属分类文件和 `errors.json`；以命令返回成功为准确认记录已保存，再运行 `git status --short` 检查所有实际受影响的规范文件。提交时只暂存本轮确实改动的文件，但不能只暂存 `errors.json` 而遗漏目标分类文件。若工作区原本已有其他改动，先区分来源并保留它们；若用户随后要求放弃本轮结果，只撤销本轮事务产生的文件变化。

根据返回结果说明状态变化：

- `status: learning`：继续留在待巩固状态。
- `status: familiar`：本次达到 8 分及以上但尚未满足 `mastered` 条件，进入或留在已标熟状态。
- `status: mastered`：同一知识点累计第 3 次达到 10 分，进入已掌握状态，并作为完整英语考试套题素材；未满 3 次的 10 分仍显示为 `familiar`。
- `lapse_count` 增加：原已标熟或已掌握知识点出现遗忘。

命令还会返回 `next_review_at`。向用户展示得分、最关键建议和下一次建议复习时间。写入成功后，在生成 `review-complete` 菜单之前按「生成本轮学习笔记」写一份本轮笔记。写入失败时仍完成教学反馈，说明“本轮评分与错题未能保存；本轮记录变更已回滚”，并把含 `claim_owner`、`claim_token` 的完整 payload 只保留在当前对话。此时不要生成正常复习菜单，只显示“重试保存本轮评分”和“放弃保存并返回菜单”；重试时原样调用 `complete-review` 并复用凭据，放弃时必须确保本轮评分、状态、历史、错题和 claim 全部清除，再清除 payload。若回滚未完整成功，说明可能残留部分变更并停止后续写入。上下文丢失时说明无法重试并返回初始菜单。

如果重试仍返回“review claim does not exist”或其他领取凭据失效错误，不得暗示评分已经保存；如实说明当前 payload 无法再提交。只有用户明确选择放弃时才尝试 `release-claim`；释放成功后清除 payload 并返回初始菜单，释放失败也要如实说明，不能把失败当作已回滚。

评分后运行：

```bash
python3 learn-from-english/scripts/learning_records.py menu \
  --context review-complete \
  --focus <当前知识点标题或核心表达>
```

只要本轮答案实际存在错误或未作答题，评分后的回复就必须**直接附带讲解**：错误按“讲解错题与未作答题”一节的四步模板逐条说明（覆盖考点、错误机制、英语表达逻辑、正确表达及可迁移用法），未作答题按同一节给出的“为什么答不出”变体给出参考表达，不得把讲解只留作待用户选择的选项。讲解已包含在回复中，因此生成 `review-complete` 菜单时加 `--current-exercise-explained`，不再显示 `explain-current-exercise` 项。全部作答且完全正确时不要加 `--has-answer-errors`，也不附带讲解。

新题展示或答题尚未完成时不生成菜单；等用户完成作答且评分保存成功或明确放弃保存后，再生成 `review-complete` 菜单。若用户在已附带讲解后又明确要求再讲一遍，仍可按“讲解错题与未作答题”一节补充更细的讲解。

`知识点讲解` 是笔记（`learning-record-notes/`）里的强制折叠块，不在聊天回复正文里逐题展开：回复只讲错题与未作答题，答对的题给出判定即可；用户明确要求“每题都讲讲”时才在回复里补充知识点讲解。

## 生成本轮学习笔记

每一轮有实际作答的复习、聚焦练习或套题结束后，除写入规范记录外，还要在仓库根目录 `learning-record-notes/` 下写一份 Markdown 笔记。
笔记是**可读副本，不是规范数据源**：它不参与 `validate`、统计、抽题或调度，缺失或被删除都不影响评分与复习计划。

写笔记前必须先读 `practice-learning-records/references/note-format.md`（何时写、文件名、模板骨架、字段取值、
追加与修正命令、菜单项记法、校验与迁移全部在那里，**不要凭记忆或旧轮次猜格式**），并按
`practice-learning-records/templates/review-note.md` 逐字替换占位符。

本 Skill 只保留四条硬约束：

- 统一入口是 `practice-learning-records/scripts/note.py`：`append` / `replace` / `list` / `context` 转发给
  `learn-from-english` 的命令，`check` 直接用本 skill 的校验器；只在这一条命令上写笔记，禁止用 `Write` 改写笔记文件，
  也禁止先落固定路径的临时区块文件。
- 追踪字段分两处：文件顶部的 `## 基础信息`（全区文件唯一一份）放记录 ID / 试卷 ID、目标知识点、累计复习次数、下次复习、
  笔记生成时间、笔记更新时间；每个日期区块的 `## 本轮信息` 只放复习时间、分类 · 状态变化、本轮得分、题量与错题数（套题再加主观题得分）。
  两处都用二级标题、固定展示，不写 `<details>`。
  写入命令会把记录级与本轮字段与规范记录逐字段比对，不一致时返回 `tracking_mismatch` 与 `tracking_expected`，按它改完再用 `replace`；
  `题量与错题数` 仍须自己按本轮实际题数与 `错题讲解` 块数填写。给已存在于其他文件的记录另建文件会被直接拒绝，并给出应复用的路径。
  新建文件时首个区块必须在标题行之前带上 `## 基础信息`，否则命令直接拒绝。
- `append` 返回 `heading_adjusted: true` 时，说明这一分钟已被占用或写入会打乱时间升序，本轮已按顺延后的 `heading` 保存；
  两轮内容都保留，后续修正用返回的 `heading`。只有 `duplicate: true`（同标题同内容）才表示已经写过，不要重试。
- `note_status` 为 `valid` 才算通过；`invalid` 表示写入成功但校验未过（退出码 1），用替换命令就地修正；
  `unverified` 表示校验器不可用，必须在回复里说明「本轮笔记未校验」。行尾空格、答案题号前缀、缺失的 `---`
  这三类无争议问题由写入命令自动修完再复检，结果在 `auto_fixed`；剩下的 issue 才需要按 `line` / `message` 手工修正。

## 场景对话错题

未作为评分复习任务的互动角色扮演不调用 `complete-review`。默认的完整场景对话脚本只是示例材料，不记录错题。只有用户明确参与互动角色扮演并确实出现、得到纠正的英语错误时，才把本轮所有错误组成一批 `errors` 记录，运行一次 `batch-upsert`。完全正确时不写错误记录。

## 完整英语考试套题

先确定本卷的 `exam_type`、考试名称、题型和评分 profile。用户明确指定考试时服从；未指定时根据已掌握素材选择 CET-4 或 CET-6。生成 CET 之外的考试前，先查证该考试当前的官方题型与计分方式；如果考试没有统一合格线，把 `pass_score` 设为 `null`，除非用户给出目标分，此时将目标分作为本卷合格线并在 `score_note` 说明。不要把 710 分制、425 合格线或省略听力规则套到其他考试。

生成新套题的入口先运行：

```bash
python3 learn-from-english/scripts/learning_records.py mastered-list
```

只使用返回的 `status: mastered` 记录作为素材池。生成完整试卷内容、参考答案及“每道可作答题对应的一个或多个 mastered ID”映射后，在首次展示前运行：

```bash
python3 learn-from-english/scripts/learning_records.py paper-create --input <JSON 文件或 ->
```

当前四六级套题使用通用 Paper Schema v2 的 CET profile。输入必须包含 `exam_type`（`cet4` 或 `cet6`）、对应的 `exam_name`（`CET-4` 或 `CET-6`）、`format_id: cet-no-listening-v1`、简短 `theme`、`source_record_ids`、`sections`、`answer_keys`、`objective_items`、`subjective_components`、`grading_scheme`，以及覆盖全部 answer key 的 `record_map`。严格使用以下配置：

- `writing`：`directions`、`prompt`、`word_requirement`、`reference_answer`。
- `listening`：固定为 `{"omitted": true, "question_slots": 25}`。
- `reading.section_a`、`section_b`、`section_c`：各含 `directions`、`passage` 和 10 个 `questions`；每题含正确范围内的 `number`、`prompt`、字符串 `choices`、`answer` 和 `explanation`。
- `translation`：`directions`、`source_text`、`reference_answer`。
- `answer_keys`：依次为 `writing`、字符串 `26` 至 `55`、`translation`。
- `objective_items`：Questions 26-35 每题 0.5 原始分，36-45 每题 1 分，46-55 每题 2 分；每项同时保存 `answer`。
- `subjective_components`：`writing.max_score` 和 `translation.max_score` 均为 15。
- `grading_scheme`：`raw_max_score: 65`、`reported_max_score: 710`、`pass_score: 425`、`conversion: linear`、`precision: 2`、`rounding_step: null`、`score_unit: 分`，并用 `score_note` 明确这是无听力模拟折算分。

`record_map` 的每个值是至少含一个 source ID 的数组。只把命令返回的 `paper_id` 和标准标题显示在卷首，不向用户展示存储的参考答案、解析或映射。所有 source 和 mapping ID 必须是当前 `mastered` 记录。文件自动保存到 `exam-papers/<paper_id>.json`，一卷一文件。其他考试可使用不同 `exam_type`、answer keys、主客观评分项与 `grading_scheme`，不要把 CET 题型或 710 分制写成通用规则。

按 CET-4/CET-6 笔试形式生成，不声称来自官方真题。卷首同时标明“官方题位 57、当前实际生成并可作答 32”：写作 1 题、听力题位 25 个但不生成、阅读 30 题、翻译 1 题。保留官方考试时间和占比：CET-4 125 分钟、CET-6 130 分钟；写作 15%、听力 35%、阅读 35%、翻译 15%。不要把省略听力后的试卷称为 65% 满分或减少版。

完整套题必须保持官方笔试顺序、题型、题量和内部比例：

- Part I Writing：短文写作 1 题，30 分钟，占 15%。给出正式 Directions、题目和字数要求；不附范文或答案。
- Part II Listening Comprehension：CET-4/CET-6 均为 25 题，占 35%；CET-4 为 25 分钟，CET-6 为 30 分钟。按当前仓库规则省略听力，不生成听力材料、听力题、听力答案或伪音频文本；只写一行省略说明并保留该部分在试卷中的位置。
- Part III Reading Comprehension：30 题，40 分钟，占 35%。Section A 词汇理解/选词填空 10 题，占 5%；Section B 长篇阅读/匹配 10 题，占 10%；Section C 仔细阅读 10 题，占 20%（通常两篇短文，每篇 5 题）。阅读题号按真实试卷习惯标为 Questions 26-55，不因听力省略而从 1 重新编号。
- Part IV Translation：汉译英段落翻译 1 题，30 分钟，占 15%。给出正式 Directions 和中文段落；不附参考译文。

根据素材的词汇抽象度、句法复杂度、话题和语域判断 CET-4 或 CET-6，用户指定时服从指定级别。首次呈现时不附答案、解析、提示或菜单；把整套未作答试卷作为唯一操作入口，并在其后的 attribution block 标注 `*Picked from mastered-learning-records · mastered*`。

允许用户按题号、Section 或 Part 分段提交。每次只确认收到的范围并列出仍缺少的可作答题，不提前公布答案或评分。用户完成 32 个可作答项，或明确提交并跳过剩余项后，才结束作答；用户提前要求答案时，先确认这会结束当前作答，再在确认后揭示。

每次收到答案或明确跳过项时立即运行：

```bash
python3 learn-from-english/scripts/learning_records.py paper-submit --input <JSON 文件或 ->
```

首次提交只传 `paper_id`、`answers` 和 `skipped`，让命令创建新的 `attempt_id`；后续提交必须复用该 `attempt_id`。`answers` 的键使用 `writing`、`26` 至 `55`、`translation`。命令成功后以返回的覆盖数量为准；上下文丢失时通过 `paper-get --paper-id <paper_id> --attempt-id <attempt_id>` 恢复，不让用户重答已保存内容。

结束作答后按题逐项批改阅读，按 CET 写作与翻译维度评价内容、组织、准确性和语言质量；错题一律按“讲解错题”的固定模板逐题解释，再按题目映射汇总哪些 mastered 知识点表现稳定、哪些需要重新巩固。只提取用户实际展示且已解释的独立可复用错误，不因总分低或选错一道题推断其他弱点。选择题错误可用用户所选的错误内容作 `source`，写作和翻译用用户原句作 `source`，并为每条错误提供修正后的代表句。

把批改结果和错误组成一次协调写入：

```bash
python3 learn-from-english/scripts/learning_records.py paper-complete --input <JSON 文件或 ->
```

输入包含 `paper_id`、`attempt_id`、`subjective_scores: {"writing": 0-15, "translation": 0-15}`、完整 `feedback` 和 `errors`。工具按存储的参考答案计算 35 原始阅读分，与写作、翻译组成 65 原始分，再按试卷的线性配置报告为 710 分制。报告满分为 710，达到 425 返回 `passed: true`。向用户展示 `reported_score / 710` 和 425 合格线，同时明确说明这是对应 CET 级别的“无听力模拟折算分”，不是官方考试成绩。

`paper-complete` 在同一写锁下保存 completed attempt 和实际错误；不调用 `complete-review`，不改变 mastered 记录的分数、状态、次数或调度。保存失败时保留完整 payload，只显示“重试保存本次试卷评分”和“放弃评分保存并保留进行中作答”；放弃时不得删除已保存答案，且不得声称成绩或错误已保存。保存成功后先按「生成本轮学习笔记」写一份套题笔记，再显示正常复习菜单。

使用 `snapshot_totals`、`daily`、`by_category`、`score_distribution`、`due_backlog`、`lapse_count` 和 `mastery_count` 说明当前规模、每日趋势、类别弱点、分数分布、积压、遗忘与掌握情况。明确说明 mastered 精简归档会清除掌握前的逐次历史，因此平均分、近期事件和分类统计只覆盖当前仍保留的事件；不要把它们描述成终身完整统计。

## 失败恢复矩阵

所有写操作的失败处理都落到同一套动作，不再按命令分别发明流程：

| 场景 | 立即动作 | 菜单 | payload | 回滚不完整时 |
|---|---|---|---|---|
| `batch-upsert` 保存知识点失败 | 继续发送教学正文 | 只显示「重试保存本轮记录」「放弃保存并继续」 | 只留在当前对话 | 说明可能残留部分记录变更并停止后续写入，不得说“已回滚” |
| `complete-review` 保存评分失败 | 继续发送批改正文 | 只显示「重试保存本轮评分」「放弃保存并返回菜单」 | 只留在当前对话，重试原样携带 `claim_owner` / `claim_token` | 同上；领取凭据失效的提示语见“评分与协调记录” |
| `paper-complete` 保存套题评分失败 | 继续发送批改正文 | 只显示「重试保存本次试卷评分」「放弃评分保存并保留进行中作答」 | 只留在当前对话 | 同上；放弃时不得删除已保存答案 |
| `note-append` / `note-replace-block` 写入失败（路径不合规、区块缺标题、文件被占用等） | 继续发送当天正文；命令报错原样说明原因 | 正常菜单照常显示 | 修正后的区块只留在当前对话 | 不得改用 `Write` 直接改写笔记文件来绕过失败 |
| `note-append` 返回 `duplicate: true`（同标题同内容） | 按已写入处理，不再追加 | 正常菜单照常显示 | 不涉及 | 不重试、不手工补写；内容有实质修改才用替换命令 |
| `note-append` 返回 `heading_adjusted: true` | 按返回的 `heading` 继续，两轮内容都已保留 | 正常菜单照常显示 | 不涉及 | 不要用原请求时间再追加一遍 |
| `note_status: invalid`（校验失败，退出码 1） | 写入已成功，用替换命令修正本轮区块后重跑 | 正常菜单照常显示 | 不涉及 | 不得把退出码 1 当成写入失败去重试；第二次仍失败时正文如实说明并留待下一轮修正 |
| `note_status: unverified`（校验器不可用） | 正常发送正文 | 正常菜单照常显示 | 不涉及 | 正文如实说明「本轮笔记未校验」，不得当作已通过 |
| 返回 `tracking_mismatch`（追踪表与记录不符） | 按 `tracking_expected` 改完本轮区块，用 `replace` 重写并复检 | 正常菜单照常显示 | 不涉及 | 不要改记录数据去迁就手抄值；`题量与错题数` 不在比对范围内 |
| `note.py` 找不到 `learning_records.py`（只装了复习 skill） | 说明缺少写入命令的位置，先跑 `note.py check --all` 确认校验可用 | 正常菜单照常显示 | 不涉及 | 不得改用 `Write` 直接落盘；按报错里的 `probed` 路径提示安装 learn-from-english 或设置 `LEARN_ENGLISH_CLI` |
| `menu` / `next-review` / 查询类命令失败 | 说明命令失败原因，按上下文退回初始菜单或直接回答 | 初始菜单 | 不涉及 | 不适用 |

跨文件写入由脚本的事务日志兜底：写入前把目标文件的原始内容备份到 `learning-records/.txn/` 并记录 `.txn-journal.json`；中途失败会立即回滚，进程被杀时下一次任意写操作或 `validate` 会先恢复再继续。看到 `.txn-recovery.log` 记录时，如实说明“上次未完成的写入已自动回滚”，不要描述成“已回滚本轮”。

## 数据边界

- 菜单、查询和查看历史不增加学习或复习次数。
- `learning-record-notes/` 下的笔记是可读副本，不是规范数据源：不参与 `validate`、统计、抽题和调度，删除或缺失不影响任何评分、状态与下次复习时间；也不得从笔记反向修改 `learning-records/`、`mastered-learning-records/` 或 `exam-papers/`。
- `follow-up-learning` 的菜单选择本身不增加复习次数；只有实际引入并写入的新知识点才增加对应学习记录的 `learned_count` 或创建新记录。
- 重复学习同一知识点会增加 `learned_count`；只用更丰富的新内容补全较弱字段并合并标签，不用较弱内容覆盖完整讲解。
- 每个题组只调用一次 `complete-review`，不能按小题重复计分。
- 数据错误时运行 `validate`；只在用户明确要求修复时运行 `repair --dry-run` 并先展示结果。
