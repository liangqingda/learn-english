# 复习英语学习记录

使用仓库根目录 `learning-records/` 与 `mastered-learning-records/` 中按 category 拆分的规范记录开展复习。`learning-records/<category>.json` 保存 `learning` 与 `familiar` 记录；同一知识点累计第 3 次达到 10 分后，写操作会把它移动到 `mastered-learning-records/<category>.json`。mastered 分类文件参考旧版 `mastered.json`，根节点直接是精简数组，每条只保留稳定 `id`、`title`、`explanation` 和 `mastered_at`。读取时工具会用 `explanation` 补 `source`，并把 `example`、`tags`、逐次评分历史和历史计数重置为空或初始值；若记录此后失分回到 `learning`，这些补齐值会成为新的记录起点，掌握前的细节不会恢复。所有读取和写入必须通过 `learn-from-english/scripts/learning_records.py`；不得直接编辑 JSON。

## 打开复习菜单

收到精确触发词时运行：

```bash
python3 learn-from-english/scripts/learning_records.py menu --context initial
```

严格按返回的 `options` 顺序、`label` 原文和 `group` 展示菜单，不自行增加、删除、重新分组或估算数量。数量只保留在脚本生成的标签末尾。顶层选项跨分组连续编号为 `1`、`2`；option 含 `children` 时，在父项下把子项编号为 `1-1`、`1-2`，更深层继续追加段。把编号路径与 option 对象只保留在当前对话。脚本保证 `Other Menus` 至少动态生成 3 项；若返回 `mastered-cet-paper`，原样放在 `Popular Menus`。把 `disabled: true` 的项显示为暂不可用但不执行；用户选择时说明记录正被其他会话领取并保持当前菜单。

若 `state` 为 `empty`，说明目前没有学习记录，并直接展示脚本返回的状态、基础练习和咖啡店场景入口，不编造历史知识点。

## 处理数字选择

只把对最近一轮菜单的纯数字或纯数字路径回复解释为菜单选择。始终根据 option 的 `kind` 分派，不根据 `label` 或 `id` 猜测行为；有 `action` 时按其中的 command 和参数调用 CLI，option ID 只用于稳定身份和父子关系：

- `review-path`：运行 action 指定的 `next-review --path <path>`。
- `continue-review`：运行 `next-review --random`。
- `familiar-review`：按 action 运行 `next-review --status familiar`。
- `mastered-review`：按 action 运行 `next-review --status mastered --random`，把它作为已掌握知识点的随机抽查。
- `mastered-cet-paper`：运行 `mastered-list`。
- `starter-practice`：在没有学习记录时，围绕一个日常表达生成 2 至 3 道基础英语练习；不写入评分。题目未作答时不显示菜单；用户提交后批改，并仅在实际出错时用一次 `batch-upsert` 保存可复用错误。
- `scenario-dialogue`：有当前记录或 focus 时围绕它输出完整多轮场景对话；仅在两者都不存在时使用脚本给出的日常场景。不要把已有记录替换成咖啡店主题，也不要默认开启互动角色扮演，除非用户明确要求 role-play。
- `follow-up-learning`：围绕 option label 和 `focus` 生成语法、词汇、对比、发音或产出内容。若生成未作答练习，不显示菜单；用户提交后批改，但不调用 `complete-review`。只把实际展示的可复用错误用一次 `batch-upsert` 保存。若讲解引入新的稳定知识点，按“后续学习知识点记录”保存。
- `explain-current-exercise`：只在用户刚完成的复习答案存在错误时解释错题，不生成新题；必须说明考点、错误原因和正确表达背后的英语计量、语义或结构逻辑。
- `error-clusters`：运行 `error-clusters`，按返回顺序展示每个 cluster 的 label 与 count，并用 `<父编号>-1`、`<父编号>-2` 等路径让用户选择。选择后围绕该 cluster 的多个错误模式生成一组聚焦练习；明确这是未评分练习，不显示菜单，不调用 `complete-review`，也不批量修改成员记录。用户作答后只把本次实际展示的新可复用错误用一次 `batch-upsert` 保存。
- `status`：执行返回的 action；初始进度入口通常运行 `stats --period 30d`，只请求分类数量时运行 `summary --include-familiar --include-mastered`。

上下文丢失或数字路径无效时重新运行初始菜单。不要要求用户重新发送“你好”，也不要尝试从规范学习记录恢复普通复习题组、待保存 payload 或套题；这些会话状态不持久化。

## 选择复习记录

脚本优先返回已经到期的记录，再综合 `next_review_at`、掌握分、遗忘次数和 ID 排序。没有到期记录时返回当前范围内优先级最高的记录。`--random` 只在优先范围中按低分和遗忘次数加权抽取。

执行任何 `next-review` action 前，先为当前对话生成不复用到其他对话的 owner 字符串，并追加 `--claim-owner <owner>`。命令会在写锁保护下写入短期 `review_claim`；保留返回的 owner 与 token，其他会话会跳过该记录。领取会自动过期，且不改变复习次数、分数或状态。

只在当前对话中保留题组、标准答案、作答进度、当前记录 ID、owner、token 和错误讲解状态；不要创建普通复习 session 文件。上下文仍在时继续当前题组；上下文丢失时明确说明不能恢复，并重新打开初始菜单，原领取等待自动过期。用户在评分前明确放弃或退出题组时运行 `release-claim --id <record id> --claim-owner <owner> --claim-token <token>`；释放失败时如实说明领取会等待过期。

命令返回 `record: null` 时明确说明当前范围没有记录，然后重新生成初始菜单；不得临时编造复习记录。

保留返回记录的 `id`、`category` 和 `status`，直到当前题组完成。新抽出记录并首次呈现题目时，只正常输出标题、引导语和题目，不输出菜单；不要在题目正文之前插入来源。把来源作为独立斜体元信息，放进题目之后的最终 attribution block：

```text
---
*Picked from <record-source> · <status> · <category>*
*Generated by practice-learning-records skill*
```

`learning` 与 `familiar` 的 `<record-source>` 使用 `learning-records`；`mastered` 使用 `mastered-learning-records`。来源行必须位于区块第一行；若本轮还有 commit notice，把它放在来源之后、skill attribution 之前。后续讲解或评价同一题组时不重复来源标注。

## 开展普通复习

根据记录设计 5 至 10 个短题，默认 6 题，按由易到难的顺序组织，并尽量参照四六级真题的命题风格，至少组合三种题型。`learning` 与 `familiar` 使用 `title`、`explanation`、`source` 和 `example`；`mastered` 的 source/example 是补齐值，只使用 `title` 与 `explanation` 并另造新语境：

- `errors`：使用新句子纠错或改写。
- `grammar`：组合造句、纠错、补全、语境选择或翻译。
- `vocabulary`、`phrases`：组合填空、搭配判断、释义辨析或造句。
- `usage`：组合语气辨析、自然度判断和场景表达。
- 可以适当加入选择题、填空题、改错题、改写题、翻译题、语境判断题和简短产出题，避免同一题型连续过多；题目应先易后难，前几题更聚焦识别和选择，后几题再逐步过渡到改写、翻译和综合运用。

题组必须考查同一知识点的多角度迁移，而不是反复改写同一个句子。出题前先拆出 2 至 4 个可迁移子点，例如搭配冗余、时间从句结构、语义边界、语域自然度、可替换表达或真实场景使用；每道题只聚焦其中 1 至 2 个子点。除非记录本身只有一个固定短语且无法迁移，否则同一题组必须满足：

- 至少 3 道题使用全新的语境、主语或动作，不沿用 `source` 或 `example` 的完整句子骨架。
- 至少 1 道题考查“为什么错/为什么自然”的机制判断，而不只是选择正确句。
- 至少 1 道题要求用户主动产出，如翻译、改写、造句或短场景回复。
- 至少 1 道题引入近义表达、相邻语境或干扰项，测试用户能否区分边界。
- 不要让 4 道及以上题目的标准答案都只是同一句核心英文的微小变体；如果题目读起来像同一道题换了编号，必须重写。

要求用户按阿拉伯数字题号集中作答，作答前不公布答案。未作答题组是当前回复的唯一操作入口，不显示菜单。用户只回答部分题目时，确认已收到的题号并列出未答题号，不公布答案、不评分；用户补齐或明确跳过剩余题目后再综合评分。

不要根据文字回答评价实际发音。相邻两轮避免完全相同的题型组合。

## 后续学习知识点记录

`follow-up-learning` 不记录分数，但不是“只讲不存”。当后续学习内容引入当前记录之外的稳定、可复习知识点时，先讲解，再用 `upsert` 或一次 `batch-upsert` 写入学习记录：

```bash
python3 learn-from-english/scripts/learning_records.py batch-upsert --input <JSON 文件或 ->
```

输入格式：

```json
{
  "records": [
    {
      "category": "phrases",
      "key": "go-ahead-with-for-approved-plan",
      "title": "go ahead with：按计划推进",
      "explanation": "go ahead with + 名词表示获得允许或决定后继续推进某个计划、活动或安排，语气比 proceed with 更口语。",
      "source": "We can go ahead with the launch.",
      "example": "The team decided to go ahead with the launch.",
      "tags": ["follow-up-learning"]
    }
  ]
}
```

记录边界：

- 记录 `go ahead with`、`move on to`、`continue along` 这类新搭配，或一个新语法/用法差异。
- 不记录只是重复当前复习记录的规则、普通例句改写、临时练习题、完整示例对话台词、发音提示或用户尚未提交答案的题目。
- 若一次扩展讲到多个紧密相关的新知识点，合并为一次 `batch-upsert` 批量写入；每条记录使用稳定语义 `key`，选择 `vocabulary`、`phrases`、`grammar` 或 `usage`，不要为了普通新知识点使用 `errors`。
- 若脚本返回匹配到已有记录而不是新建，照常说明“已遇到/更新已有记录”；不要手工改 JSON。
- 写入失败时仍完成讲解，说明“本轮新知识点未能保存；本轮记录变更已回滚”，并把原始 payload 只保留在当前对话。不要显示正常菜单，只显示“重试保存”和“放弃保存并继续”；重试时原样提交，放弃时清除 payload。若回滚未完整成功，说明可能残留部分变更并停止后续写入。

## 讲解错题

用户要求讲解刚才的错题或选择 `explain-current-exercise` 时，不要只说“不能说”“不自然”或重复规则标签。按顺序说明：

1. 本题实际考查的知识点。
2. 错误项或错误答案为什么错：指出触发该判断的英语机制，例如可数/不可数的计量方式、冠词和量词的搭配条件、时态对应、词义边界、句子结构或语域限制。
3. 英语自己的表达逻辑：说明英语把这个概念当作可数单位、不可数内容、动作过程、状态结果还是具体事件处理。
4. 正确答案为什么成立，并给出可迁移表达；如果中文直觉和英语分类不同，明确对比。

讲解选择题时逐项解释关键干扰项；讲解改错或翻译题时先说明用户原句的意图，再区分核心错误、自然度问题和可选风格改写。避免把“规则名称”当作原因；规则名称后面必须跟一句可理解的机制解释。

## 评分与协调记录

用户完成一组可客观评价的复习后，逐题判断并给出自然答案，再综合评为 0 至 10 分：

- 9 至 10：完全正确且自然。
- 8：核心正确，有轻微问题。
- 5 至 7：部分掌握。
- 0 至 4：核心规则未掌握。

评分只衡量当前被复习记录对应的目标知识点是否掌握。执行时按下面顺序判断：

1. 先判断当前目标知识点本身是否答对。
2. 目标知识点答对时，必须按通过处理，不能因为答案里还有其他英语问题而把这个目标点判为未通过或降档。
3. 再检查答案里是否出现其他可复用英语错误；这些错误要单独写入本轮 `errors`。
4. 只有当某个错误本身就是当前目标知识点的一部分时，才把它计入当前知识点评分。

换句话说，主评分只看目标点是否掌握，附带错误只做独立记录，不互相覆盖。

把评分和本轮实际出现的可复用错误模式组成一个 JSON 对象，并只调用一次：

```bash
python3 learn-from-english/scripts/learning_records.py complete-review --input <JSON 文件或 ->
```

输入格式：

```json
{
  "id": "grammar:present-perfect-experience",
  "score": 7,
  "claim_owner": "<current conversation owner>",
  "claim_token": "<token returned by next-review>",
  "errors": [
    {
      "key": "stable-semantic-error-key",
      "title": "错误模式标题",
      "explanation": "纠错说明",
      "source": "用户的错误答案",
      "example": "修正后的代表句",
      "tags": ["review-error"]
    }
  ]
}
```

完全正确时传入空 `errors`。只记录用户实际展示并已解释的错误，不推断其他弱点。整个命令先校验评分和所有错误，再在本机写锁保护下逐个原子替换受影响的分类文件：任一输入无效时不会开始写入；跨文件写入中途失败时会尽力回滚本轮已替换的文件，但这不是单次文件系统事务。

根据返回结果说明状态变化：

- `status: learning`：继续留在待巩固状态。
- `status: familiar`：本次达到 8 分及以上但尚未满足 `mastered` 条件，进入或留在已标熟状态。
- `status: mastered`：同一知识点累计第 3 次达到 10 分，进入已掌握状态，并作为完整四六级套题素材；未满 3 次的 10 分仍显示为 `familiar`。
- `lapse_count` 增加：原已标熟或已掌握知识点出现遗忘。

命令还会返回 `next_review_at`。向用户展示得分、最关键建议和下一次建议复习时间。写入失败时仍完成教学反馈，说明“本轮评分与错题未能保存；本轮记录变更已回滚”，并把含 `claim_owner`、`claim_token` 的完整 payload 只保留在当前对话。此时不要生成正常复习菜单，只显示“重试保存本轮评分”和“放弃保存并返回菜单”；重试时原样调用 `complete-review` 并复用凭据，放弃时先用同一凭据调用 `release-claim`，再清除 payload，且不得暗示评分已保存。若回滚未完整成功，说明可能残留部分变更并停止后续写入。上下文丢失时说明无法重试并返回初始菜单。

评分后运行：

```bash
python3 learn-from-english/scripts/learning_records.py menu \
  --context review-complete \
  --focus <当前知识点标题或核心表达>
```

`review-complete` 菜单只在用户答案实际存在错误且当前错题尚未讲解过时保留 `explain-current-exercise`。运行命令时加 `--has-answer-errors`，并把脚本返回的 `🔍 讲解错题` 放在全部菜单项第一位。完全正确时不要加该参数。错题讲解后加 `--current-exercise-explained`，后续菜单不再显示该项。

新题展示或答题尚未完成时不生成菜单；等用户完成作答且评分保存成功或明确放弃保存后，再生成 `review-complete` 菜单。讲解错题后加 `--current-exercise-explained`。

## 场景对话错题

未作为评分复习任务的互动角色扮演不调用 `complete-review`。默认的完整场景对话脚本只是示例材料，不记录错题。只有用户明确参与互动角色扮演并确实出现、得到纠正的英语错误时，才把本轮所有错误组成一批 `errors` 记录，运行一次 `batch-upsert`。完全正确时不写错误记录。

## 完整四六级套题

完整套题入口先运行：

```bash
python3 learn-from-english/scripts/learning_records.py mastered-list
```

只使用返回的 `status: mastered` 记录作为素材池。在当前对话创建唯一 `paper_id`，把它显示在卷首，并保留试卷、答案、作答进度和“每道可作答题对应的一个或多个 mastered ID”映射；不得把这些套题状态写入仓库。上下文仍在时允许用 `paper_id` 继续，丢失后明确说明无法恢复并让用户重新生成。

按 CET-4/CET-6 笔试形式生成，不声称来自官方真题。卷首同时标明“官方题位 57、当前实际生成并可作答 32”：写作 1 题、听力题位 25 个但不生成、阅读 30 题、翻译 1 题。保留官方考试时间和占比：CET-4 125 分钟、CET-6 130 分钟；写作 15%、听力 35%、阅读 35%、翻译 15%。不要把省略听力后的试卷称为 65% 满分或减少版。

完整套题必须保持官方笔试顺序、题型、题量和内部比例：

- Part I Writing：短文写作 1 题，30 分钟，占 15%。给出正式 Directions、题目和字数要求；不附范文或答案。
- Part II Listening Comprehension：CET-4/CET-6 均为 25 题，占 35%；CET-4 为 25 分钟，CET-6 为 30 分钟。按当前仓库规则省略听力，不生成听力材料、听力题、听力答案或伪音频文本；只写一行省略说明并保留该部分在试卷中的位置。
- Part III Reading Comprehension：30 题，40 分钟，占 35%。Section A 词汇理解/选词填空 10 题，占 5%；Section B 长篇阅读/匹配 10 题，占 10%；Section C 仔细阅读 10 题，占 20%（通常两篇短文，每篇 5 题）。阅读题号按真实试卷习惯标为 Questions 26-55，不因听力省略而从 1 重新编号。
- Part IV Translation：汉译英段落翻译 1 题，30 分钟，占 15%。给出正式 Directions 和中文段落；不附参考译文。

根据素材的词汇抽象度、句法复杂度、话题和语域判断 CET-4 或 CET-6，用户指定时服从指定级别。首次呈现时不附答案、解析、提示或菜单；把整套未作答试卷作为唯一操作入口，并在其后的 attribution block 标注 `*Picked from mastered-learning-records · mastered*`。

允许用户按题号、Section 或 Part 分段提交。每次只确认收到的范围并列出仍缺少的可作答题，不提前公布答案或评分。用户完成 32 个可作答项，或明确提交并跳过剩余项后，才结束作答；用户提前要求答案时，先确认这会结束当前作答，再在确认后揭示。

结束作答后按题逐项批改阅读，按 CET 写作与翻译维度评价内容、组织、准确性和语言质量；给出答题覆盖、阅读正确数、写作与翻译分项反馈和关键错因。由于听力缺失，不给出或推算官方 710 总分。先解释错误，再按题目映射汇总哪些 mastered 知识点表现稳定、哪些需要重新巩固。套题结果不调用 `complete-review`，不改变任何规范记录的分数、状态、次数或调度；仅把用户实际展示且已解释的独立可复用错误用一次 `batch-upsert` 保存。保存失败时使用本 Skill 的重试/放弃恢复流程。批改完成后再显示正常复习菜单。

## 历史与统计

用户要求查看某条记录的复习过程时运行：

```bash
python3 learn-from-english/scripts/learning_records.py history --id <record id>
```

用户要求查看近期进展时运行：

```bash
python3 learn-from-english/scripts/learning_records.py stats --period 30d
```

使用 `snapshot_totals`、`daily`、`by_category`、`score_distribution`、`due_backlog`、`lapse_count` 和 `mastery_count` 说明当前规模、每日趋势、类别弱点、分数分布、积压、遗忘与掌握情况。明确说明 mastered 精简归档会清除掌握前的逐次历史，因此平均分、近期事件和分类统计只覆盖当前仍保留的事件；不要把它们描述成终身完整统计。

## 数据边界

- 菜单、查询和查看历史不增加学习或复习次数。
- `follow-up-learning` 的菜单选择本身不增加复习次数；只有实际引入并写入的新知识点才增加对应学习记录的 `learned_count` 或创建新记录。
- 重复学习同一知识点会增加 `learned_count`；只用更丰富的新内容补全较弱字段并合并标签，不用较弱内容覆盖完整讲解。
- 每个题组只调用一次 `complete-review`，不能按小题重复计分。
- 数据错误时运行 `validate`；只在用户明确要求修复时运行 `repair --dry-run` 并先展示结果。
