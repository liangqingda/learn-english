> 本文件是 `skills/take-english-study-notes/references/note-format.md` 的分支参考，讲校验、派生索引与历史迁移。只在跑校验、修索引或做迁移时读取。

## 校验与历史迁移

写完必须校验通过。`--check` 已自动运行同一条命令，需要单独复查时运行：

```bash
python3 skills/take-english-study-notes/scripts/note.py check --all          # 全量校验默认 notes 目录
python3 skills/take-english-study-notes/scripts/note.py check --all --fix    # 先修无争议项再校验
python3 skills/take-english-study-notes/scripts/note.py check learning-record-notes/<category>/<category>-<slug>.md
```

`--all` 用 `$LEARN_ENGLISH_REPO_ROOT`（缺省取本脚本所在仓库根）定位 `learning-record-notes/`，逐个分类子目录
（`errors/`、`phrases/`、`grammar/`、`usage/`、`vocabulary/`、`paper/`）收集 `.md`，跳过 `README.md`；
残留在目录根下的平铺笔记也会被收进来，并由校验器报「必须放进分类目录」；
CI 每次 push 跑这一条。`--fix` 只处理无争议问题：行尾空格、`我的答案` 的题号前缀、缺失的区块 `---` 分隔、
缺失的 `笔记更新时间` 行（按该区块 `笔记生成时间` 补齐）、把记录级字段上移到文件顶部唯一一份 `## 基础信息`、给每轮补 `生成时间` 行、把原先包住两处的 `<details>` 折叠块拆成固定展示（每轮表格不加小标题）、把日期标题下、`## 本轮习题` 之前的本轮追踪表移到该标题之下（内容一字不动）、删掉非套题里恒为 `—` 的 `主观题得分` 行，
删掉 `基础信息` 与第一个日期区块之间多余的 `---`、把旧版 `# … · 讲解` 轮次区块迁移为文件级 `## 讲解` 小节，
以及把日期区块内的习题小节按落盘时间倒序重排（最新一节在最前）、按当天的轮次给同名习题小节补 / 去 ` - 01`、` - 02` 序号、按真实习题小节重建隐藏锚点与文件级索引块，
不改题干、答案、讲解与判定；区块之间的先后顺序不由 `--fix` 重排；它不需要人工触发——`append` / `replace --check` 发现校验失败时会自动修完再复检，
并用 `auto_fixed` 回传改了什么。追踪字段的身份值（记录 ID、目标知识点、状态变化、本轮得分、累计复习次数、下次复习）
同样由写入命令自动比对，不一致时返回 `tracking_mismatch` 与 `tracking_expected`。

`--all` 的返回里还有一节 `missing_notes`：记录库里还没有笔记文件的记录（按 `learning-record-notes/<category>/<category>-<key>.md` 判断是否存在），
只做体检报告、不参与 `ok` 判定——笔记按需生成，这类记录属正常状态。字段为 `count`、`by_category`（各分类缺失条数）、
`records`（按分类轮流取样的前 50 条，避免 `errors` 占多数时其他分类一条都看不到）、`truncated`。

校验器对**位置**是硬性规则：日期区块里出现 `**讲解要点**：` 或 `<summary>场景对话原文` / `<summary>故事原文` 折叠块，
一律报「日期区块只放习题」，写入命令（`append` / `replace` / `append-section` / `append-part`）也直接拒绝同样的内容。
这条规则只拦新写入与现存笔记：现存笔记已按规则迁移完毕，
所以 `check --all` 现在能在位置这一层兜住，不必再靠文档自觉。

校验器对**标题**同样是硬性规则：每段场景对话 / 故事原文折叠块的 summary 必须写成
`<summary>场景对话原文 · <标题></summary>` / `<summary>故事原文 · <标题></summary>`（多段时编号在标题之前，如 `故事原文 2 · 五点十五分的卷帘门`）。
缺标题、标题为空或标题超过 24 字都会报错；写入命令（`append-explain-section` / `--rewrite` / `append-explain-part`）也会直接拒绝缺标题的折叠块。
标题内容本身（是否贴合场景、两段是否重名）校验器判断不了，只能靠生成时按规则写。

校验器对**例句的反引号**只拦一种写反：反引号片段后面紧跟中文全角括号译文（骨架被反引号包住、紧跟（译文）），
报「带中文译文的内容不要套反引号」。反引号里该放的是不带译文的骨架，整句例句一律纯文本，口径见 `note-format.md` 的「内容要求」；
能独立成句却没附译文的写法校验器判断不了，只能靠生成时按规则写。

同一天多次练同一菜单项时，**日期标题不变**，变的是习题小节标题：同一天的多个区块算一个「天组」，
同一菜单项的习题小节从第 2 份起按时间升序写成 `## <选项原文> - 01`、`## <选项原文> - 02`……
当天只有一份时不带后缀。同一轮隔天再练进的是同一个区块、同一个「天组」，重复菜单项照样另建一份带序号的同标题小节（一节一表、题号从 1 起），不会被并进既有小节。`append` / `append-section` 会在锁内自动完成补号
（把已有那份改成 ` - 01`，新份写成 ` - 02`），返回值里 `section` 是实际写入的标题、`section_renamed` 列出被改名的旧标题；
手工写错时 `--fix` 会按轮次重排。`replace` 不改小节标题，修正带序号的既有小节时，
用 `sections` 返回的实际标题（含 ` - 01` / ` - 02`）去匹配，不要漏掉后缀。校验器对这条同样是硬性规则：单份带后缀、多份缺后缀或序号不连续都报错。

区块内部同样按时间倒序：一个日期区块里的菜单项小节按各自 `生成时间` 从新到旧排列（最新一节在最前），
与文件级小节「复习历史」索引的顺序一致；`## 本轮习题` 只要出现就固定是区块内第一个二级标题。
校验器发现新小节排在旧小节后面会报错，`--fix` 只调换小节先后，题干、答案、判定与讲解一字不动。
正文展示顺序与后缀编号方向相反：后缀按时间升序（最早 `- 01`），所以最上面的小节可能带最大的后缀号。

**可跳转索引（派生内容，由写入命令自动维护，不手写）**：每份带习题的菜单项小节，标题行**右侧**固定挂一个空元素锚点，
与标题同一行：`## 练习「a price to pay」的关键语法结构 <a id="practice-<YYYY-MM-DD>-<HHMM>-<8 位小写 hex>"></a>`。
它渲染时不可见，只在跳转时用，落在标题本身上；`hex` 取小节原文标题（去掉 ` - 01` 后缀）的 SHA-1 前 8 位，
所以同一天两份习题的锚点也不相同。文件级同名小节（`## 讲解` 之后的 `## <选项原文>`）在**讲解内容之后**再放一块索引；
纯答题、没有讲解要点的骨架小节没有讲解内容，索引就直接挂在标题之下。前面单独一行写 `复习历史：`：

```
**讲解要点**：
- 名词 + 后置不定式用主动形式…

复习历史：
<!-- practice-index -->
- [2026-11-15 12:05 · 复习 - 02](#practice-2026-11-15-2100-8cd81652)
- [2026-11-15 12:05 · 复习 - 01](#practice-2026-11-15-1205-8cd81652)
<!-- /practice-index -->
```

条目按时间倒序列出全文件该菜单项的全部习题小节（新的在前），文本与日期区块标题同口径（`<日期> <HH:MM> · <复习|练习|套题>`），同一天同一菜单项有多份时按时间先后补 ` - 01`、` - 02`，
跳转目标取自真实小节。索引块固定落在小节的讲解内容之后、小节末尾，索引块后面不能再写讲解正文。

**复习目录（同类派生内容）**：`## 讲解` 的讲解内容之后同样写 `复习历史：` + `<!-- round-index -->` … `<!-- /round-index -->`，
按时间倒序列出整份笔记每个日期区块的 `## 本轮习题`（新的在前）；每个日期区块的 `## 本轮习题` 同样在标题行右侧挂
`<a id="round-<YYYY-MM-DD>-<HHMM>"></a>`，点一下就跳到那一轮的题目：

```
复习历史：
<!-- round-index -->
- [2026-11-15 12:05 · 复习](#round-2026-11-15-1205)
- [2026-11-07 20:22 · 复习](#round-2026-11-07-2022)
<!-- /round-index -->
```

一个区块固定一份 `## 本轮习题`，所以它的锚点只用日期与时间、无需标题哈希；同一天有两个区块时按时间先后写成
`2026-11-15 09:26 · 复习 - 01`、`2026-11-15 21:53 · 复习 - 02`，避免两行同名。

`note_store._write` 在每条写入路径之后统一重建两组锚点与两块索引，`check --all --fix` 也重建，因此改标题、增删习题小节或区块后
不需要手工同步；校验器逐条比对索引与真实小节、核对每个锚点存在且全文件唯一、锚点必须与所在区块和标题哈希一致，
并检查 `复习历史：` 这一行、索引块必须落在讲解内容之后，缺锚点、缺索引、缺标题、索引后还有正文、条目对不上或有残留索引块都报错。
只有文件级同名小节存在时才写习题索引块；该菜单项还没有任何习题小节时不留索引块；没有日期区块时也不留复习目录。
日期区块里已有习题小节、讲解区却没有同名文件级小节（含纯骨架小节）时校验器报错；`append-section` 写入时会自动补上这份骨架。
能不能点得动取决于渲染器：保留 HTML 属性的渲染器（GitHub、VS Code 预览）按 `#practice-…` / `#round-…` 跳到对应标题；
不支持 HTML 锚点的渲染器（Obsidian、Typora）只会显示成一行普通文字，纯文本视图同理——所以索引条目直接复用日期区块标题，
可读、跳不动时也能当目录看。

`ok: true` 表示笔记合规。`ok: false` 时按 issue 的 `line` 与 `message` 修正：

- issue 落在本轮刚追加的区块内：把修正后的完整区块交给同一把锁的替换命令就地替换，不要整文件重写、不要追加第二遍。
- issue 落在更早的历史区块内：不借本轮修改历史、不为通过校验重排旧区块；第二次仍不通过时，正常发送批改与讲解正文，
  并在正文里如实说明「本轮笔记未通过校验，已保留待修正」，把 issue 记在当前对话，下一轮优先修正该文件。

模板演进（新增/重命名折叠块、增加字段口径）导致历史笔记不再通过校验时，允许一次性迁移，但必须满足三条：
把新轮次插到最前、把历史日期区块按时间倒序重排（正文一字不改）、把折叠块拆成固定展示的裸表格、把记录级字段上移到文件顶部 `## 基础信息` 并给每轮补 `生成时间`、把旧版 `# … · 讲解` 区块改写成文件级 `## 讲解`（只搬正文、丢掉旧的讲解追踪行）、只补齐模板新增的追踪字段行（`笔记更新时间` 按相邻的
`笔记生成时间` 迁移）、或只删掉非套题里恒为 `—` 的 `主观题得分` 行；不得改动题干、`我的答案`、判定与正文讲解；日期区块只允许按时间倒序调整先后，内容一字不改；迁移前后用 `git diff`
确认没有正文删除。迁移不适用于日常整理。
