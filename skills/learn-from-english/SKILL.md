# 从英语输入中学习

把用户发送的英语当作真实学习材料，而不是需要套用固定模板的题目。使用简体中文讲解，保留必要的英文例句。

## 触发前强制检查

先去除用户消息的首尾空白。只要消息中含有任何英文内容——单词、短语、句子、段落、混合内容，甚至单独的英文单词如 `hello` 或单个英文字母——就使用本 Skill 讲解，不因输入过短而转交或跳过。

唯一例外：用户消息去除首尾空白后仅为中文“你好”或“复习”，仅为单独的英文单词 review、hi 或 practice（忽略大小写），仅为一条复习笔记的相对路径（形如 `learning-record-notes/errors/errors-before-begin-gerund-or-clause.md`，可带反引号或引号），或仅为一条知识点记录 ID（形如 `phrases:not-any-more-in-negative`，可带反引号或引号）时，立即停止本 Skill，改用 `practice-learning-records`；此类输入不属于本 Skill 的讲解范围。其中 review、hi 打开复习初始菜单，practice 则跳过菜单、直接从综合复习范围随机抽一条记录出题，笔记路径与记录 ID 则跳过菜单、直接对那一个知识点出题。**这条笔记路径与记录 ID 检查先于下面的工程语境判断**：整条只是笔记路径或记录 ID 时按复习处理，不要当成文件操作或查询。另一类不进入教学的是工程语境：消息是代码块、文件路径、shell 或 Git 命令、`repo`/`skill`/`commit`/`test`/`API` 这类标识符，或带 `#dev` 前缀时，按仓库根目录 `AGENTS.md` 的「Engineering-context exemption」处理该工程任务，不产出英语讲解。凡出现其它英文内容，即使伴随中文“你好”“复习”，也仍按本 Skill 处理，把其中的英语作为学习材料。

## 完成核心流程

每次回答依次完成以下任务：

1. 先给出最直接、自然的理解。
2. 找出最有学习价值的内容。
3. 解释这些内容为什么这样使用。
4. 输入是单词或短语时，必须给出简短的历史、地域或文化背景与来源结论；没有值得展开的特定背景时，明确说明这一点。
5. 给出少量可以迁移到其他场景的例子。
6. 若本轮可以显示正常菜单，运行 `python3 skills/learn-from-english/scripts/learning_records.py menu --context learn --focus "<本轮核心表达>"`，严格按返回的 `options` 顺序、`label` 原文与 `group` 渲染菜单；本轮已经实质讲解过语法时追加 `--grammar-explained`，跳过通用语法入口。历史试卷入口已由该命令合并返回，不再单独运行 `paper-menu`。选项带 `practice: false` 时（例如发音与重读方向），用户选中后只讲解、不出习题、不计分，把讲解要点写进文件级小节后照常给下一菜单；其余选项的作答、计分与落盘按 `skills/practice-learning-records/references/menu-dispatch.md` 分派。

在完成正文并发送回复之前，按照“记录本轮知识点”流程用一次批量写操作保存本轮实际讲解的内容，再根据是否有未作答练习决定是否生成快捷菜单。记录失败不得阻断教学回复，但必须按失败恢复流程处理。

## 生成本轮讲解笔记

笔记的规则、模板、校验器与写入实现都在 `take-english-study-notes` skill 里，本节只说明「什么时候写、哪条记录写什么栏目」；格式细节一律以
`skills/take-english-study-notes/SKILL.md` 与 `skills/take-english-study-notes/references/note-format.md` 为准。

记录保存成功后，为**每条实际讲解的记录**在仓库根目录 `learning-record-notes/` 的对应分类子目录里写一份笔记
（`learning-record-notes/<category>/<category>-<slug>.md`）：一个知识点一个文件，之后的复习继续写在同一个文件里。

讲解是**文件级固定小节** `## 讲解`，位置紧跟 `## 基础信息` 表格之后、在所有日期区块之前：一个知识点只有一次首次讲解，只有复习才会多轮，所以讲解不进入轮次编号、不带 `讲解时间` / `分类 · 状态变化` / 本轮得分 / 题量这些本轮字段。

1. 先读 `skills/take-english-study-notes/references/note-format.md` 与 `skills/take-english-study-notes/templates/review-note.md` 里的讲解骨架，逐字替换占位符；不要凭记忆拼格式。
2. 路径按记录 ID 生成：`<category>/<category>-<key>.md`（`phrases:you-are-what-you-eat` → `learning-record-notes/phrases/phrases-you-are-what-you-eat.md`）。同一记录已有笔记时命令会拒绝另建文件并给出应复用的路径。
3. 只通过 `skills/take-english-study-notes/scripts/note.py explain --file learning-record-notes/<category>/<category>-<slug>.md --content-file - --check` 创建，内容走标准输入；禁止用 `Write` 改写笔记文件，也不要用固定路径的中转文件。返回 `duplicate: true` 说明该文件已有 `## 讲解`，按已写入处理，不要再写第二份。
4. **写之前若发现该记录已有笔记但没有 `## 讲解`**（历史补建、只被复习写过区块），先用同一个命令加 `--update` 补齐，再写本轮内容：命令会把这一节插到 `## 基础信息` 表之后、所有日期区块之前（返回 `inserted: true`），不覆盖已有区块；确实没有正文可写时按 `note-format.md` 的占位提示写法填写，不要留空或省略这一节。
5. 基础信息表用脚本返回的 tracking 值（记录 ID、目标知识点、累计复习次数、下次复习、笔记生成时间、笔记更新时间）；讲解小节不写任何追踪行。
6. `## 讲解` 必须**只讲这条记录自己那一层**，栏目按分类自选、不要求凑齐固定几项（至少两栏，每栏写成列表或表格）：
   - `phrases`：必写 `**核心含义**：`，建议再写 使用场景与语气 / 结构与搭配 / 历史文化背景 / 发音 / 容易混淆 / 举一反三。
   - `grammar`：必写 `**语法机制**：`，建议再写 结构拆解 / 与相近结构对照 / 常见误用 / 举一反三；**不写历史文化背景和发音**，它们对语法没有解释力。
   - `usage`：必写 `**语气与语域**：`，建议再写 核心含义 / 使用场景 / 历史文化背景 / 容易混淆 / 举一反三。
   - `vocabulary`：必写 `**核心含义**：`，建议再写 搭配 / 近义辨析 / 历史文化背景 / 发音 / 举一反三。
   - `errors`：必写 `**错误机制**：`，建议再写 为什么错 / 正确表达 / 举一反三。
   同一句英语被拆成多条记录时，各文件只写自己分类的内容，不要把同一段讲解复制三份；需要改写已有讲解时加 `--update` 只替换 `## 讲解` 整节。
7. 只写正文已经实质讲解的内容，不抄菜单、不写未被解释的项目；讲解轮没有作答，因此不写 `## 本轮习题`、不写本轮得分与题量。
8. 之后的复习由 `practice-learning-records` 用 `note.py append` 往同一个文件追加 `# <时间> · 复习` 区块，讲解小节不动。
9. 笔记写入失败不阻断教学回复：正文照常发送，并如实说明「本轮讲解笔记未保存」及命令给出的原因；`note_status` 为 `invalid` 时按 issue 用 `replace` 就地修正，`unverified` 时说明「本轮讲解笔记未校验」。
10. 写入关系到仓库文件，按仓库根目录 `AGENTS.md` 的提交约定处理，不要把它和无关改动混进同一次提交。

不要为了完整而解释每个单词。不要把简单内容讲得过度复杂。

## 记录本轮知识点

使用 `scripts/learning_records.py` 维护仓库根目录的 `learning-records/` 与 `mastered-learning-records/` 分类 JSON 文件。不得直接手工修改记录文件。

每轮只记录正文中得到实质讲解的 1 至 4 个知识点：

- `vocabulary`：单词及其当前语境含义。
- `phrases`：短语、固定表达和搭配。
- `grammar`：语法规则或可复用句型。
- `usage`：只装「语用判断」——语气、语域、礼貌程度、自然度或场景选择，且这条记录本身就是那次判断，必须有对比对象（同一个意思的两种说法差在哪，或一句话在某个场合是否得体）。能挂到具体词义或结构的差别不算：词义 / 词形辨析进 `vocabulary`，固定搭配与介词搭配进 `phrases`，连词、时态、句型机制进 `grammar`；某个词或短语顺带的语域差别，写进该词／短语自己的记录（讲解里加语域栏、`tags` 标 `register` 或 `nuance`），不再为同一个表达另开一条 `usage` 记录。
- `errors`：只有判不出知识类型、或只剩「这一句错了」证据价值的一次性错误才用它。可迁移的错误先判型再落库：拼写 / 词形 / 词义 → `vocabulary`，搭配与固定表达 → `phrases`，结构、时态、句型 → `grammar`，语气 / 语域 / 场景选择 → `usage`；错句放该记录的 `source`，`key` 按知识点命名。一句错答案里同时有拼写和时态问题时，各写一条对应分类的记录，不要都塞进 `errors`。

**一个表达一条记录（先搜后写）**：写入前先运行 `python3 skills/learn-from-english/scripts/learning_records.py search --query "<本轮表达>"`
确认是否已有记录。命中就把本轮新讲的层面（搭配、语域、典型错法）补进同一条记录的 `explanation`、`example` 与 `tags`，
不要按「词义／搭配／语域／错法」各建一条；同一个表达被拆进多个分类，正是复习时一条知识要跨几个分类抽题的原因。
同一表达不同层面确实无法写进一条时，才分到不同分类，并让两条记录的 `key` 指向同一个表达。

先搜后写要真的搜得着，因此下面四条是硬约束：

- 搜索词取**核心表达**，不带修饰词：用表达本身做查询，不把搭配成分、句式或例句骨架带进关键词。整句没逐字命中时 `search` 会自动按词兜底（返回里 `matched_tokens` 标明命中了哪几个词），但结果会变长变散，核心表达仍是首选查询。（示例：讲 `can't stand` 搜 `can't stand`，而不是 `cant stand doing sth`。）
- 同一表达的历史 `key` 可能因撇号、连字符写法不同而有多种 slug 形式；搜到任意一种都算命中，直接复用那条记录的 `id`，不要为「另一种写法」新建记录。（示例：`can't stand` 家族历史上出现过 `can-t-stand-tolerate` 与 `cant-stand-doing` 两种 slug。）
- `batch-upsert` 的结果里出现 `possible_duplicates` 时，说明同分类已有标题很像的记录：先核对是不是同一个知识点；是就改用既有 `id` 重新提交，确认不是才保留新 `key`，并在回复里说明为什么不合并。不处理这条提示就继续写，等于又造一份重复笔记。
- `key` 里的撇号一律压掉，不要把撇号拆成独立连字符字母段；两种 slug 写法会让同一表达在检索里变成两条。（示例：`can't` → `cant`，而不是 `can-t-stand`。）

已经写重的两条记录用 `merge --target <保留的 id> --source <被并入的 id>` 合并（同分类、保留复习历史与状态），合并后按 `delete-note --note <被并入的笔记> --keep-record` 删掉那份多余笔记，不要手工 `rm`。

不要记录快捷菜单、练习题题干、仅作为说明材料的普通例句、只被提及但未解释的项目，或非英语教学回复。普通英语输入或自由对话中的错误不得因此新建任何记录；只有用户提交明确习题的答案，或正在进行的英语场景对话中提交需要纠正的英文回应后，才按仓库根目录 `AGENTS.md` 的规则记录实际答错的模式，并按上面的判型规则分配分类。用户通过数字菜单继续学习时，只记录该轮新近实质讲解的知识点。

把本轮所有知识点组成一个 JSON 数组，并只调用一次：

```bash
python3 skills/learn-from-english/scripts/learning_records.py batch-upsert --input <JSON 文件或 ->
```

输入格式为 `{"records": [{"category": "grammar", "key": "present-perfect-experience", "title": "...", "explanation": "...", "source": "...", "example": "...", "tags": ["..."]}]}`。`tags` 只用小写 ASCII 连字符词（`word-choice`、`register`）；大小写与空格会被自动归一，中文标签在写入前报错，需先译成英文再写。同类同义知识点必须复用同一个 `key`；键只表达知识点本身，不包含日期、会话或例句。`key` 只能用小写 ASCII 字母、数字与连字符，中文主题要意译成英文短语（直接传中文会在写入前报 key 无效，不会落成中文 ID）。脚本会生成稳定 ID；相同 ID 或同分类高度相似知识点会复用已有记录并保持当前状态，不用较弱内容覆盖较完整内容，但会用更丰富的新 `explanation`、`source`、`example` 和标签补全已有记录（相似匹配只在同一分类内进行，跨分类不会被合并）。根据返回的 `reason`、`similarity` 与 `enriched_fields` 判断匹配和补全结果。整批输入先校验后写入，任一知识点无效时整批不保存。多个分类文件由本机写锁协调并逐个原子替换；写入前脚本会把目标文件的原始内容备份到 `learning-records/.txn/` 并记录 `.txn-journal.json`；中途失败立即回滚，进程被杀时下一次写操作会先自动恢复再继续。

不要在每轮预读全部记录。只有在用户要求复习、查询学习历史，或确实需要判断既往知识点时，才调用：

```bash
python3 skills/learn-from-english/scripts/learning_records.py list --category <category>
python3 skills/learn-from-english/scripts/learning_records.py search --query <text>
python3 skills/learn-from-english/scripts/learning_records.py search --query <text> --status learning --status familiar
```

读取 `search` 结果时优先使用 `relevance`、`matched_fields` 和 `snippet`，不要把低相关结果当作精确命中。服务层搜索默认覆盖全部状态；需要缩小范围时显式传入状态过滤。

历史试卷菜单必须按 option 的 `kind` 分派：`historical-unanswered-paper` 按 action 运行 `paper-get` 并展示未附答案的原卷；`continue-paper-attempt` 运行带 `attempt_id` 的 `paper-get`，恢复已保存答案并列出剩余项；`retry-random-paper` 运行 `paper-list --status completed --random` 后读取该试卷，用户首次提交新答案时不传 `attempt_id`，从而创建新的 attempt。`paper-history` 父项本身不执行。

`focus-story` 按 option 的 `focus` 输出单线叙事小故事：篇幅、目标表达落点、中文对照与收尾三列表按仓库根目录 `AGENTS.md` 的小故事规则，不写成对话、不追加练习；它是只读展示，不计分也不写错题记录。写进笔记时同样只经 `take-english-study-notes` 的命令追加 `## <选项原文>` 小节，保留完整 `故事原文 · <标题>` 折叠块（标题与聊天里那一行 `**<标题>**` 一致，标题只写在 summary 上、块内不重复加粗标题行；收尾三列表折叠在同一块内，写在叙事与译文之后）。

若写入失败，继续发送教学回复，并明确说明“本轮学习记录未能保存；本轮记录变更已回滚”。把原始 `batch-upsert` payload 只保留在当前对话，不写入仓库或其他持久文件；此时不要显示正常学习菜单，也不要展示原计划中的未作答练习，只显示“重试保存本轮记录”和“放弃保存并继续”两个恢复选项。重试时原样提交同一 payload；重试成功或用户明确放弃并清除 payload 后才恢复练习或正常菜单。完整的失败处理矩阵（含 `complete-review`、`paper-complete` 与笔记校验）只在 `skills/practice-learning-records/references/failure-recovery.md` 一处维护，不要自行另写一套。若命令报告回滚未完整成功，不得使用“已回滚”，必须说明可能残留部分记录变更并停止后续写入；上下文丢失时说明无法恢复待保存 payload，并返回新的学习菜单。

## 删除记录与笔记

用户明确要求删除某条知识点或某篇学习笔记时才动删除，且只能走下面两条命令，不得直接编辑分类 JSON、不得自己 `rm` 笔记文件：

```bash
python3 skills/learn-from-english/scripts/learning_records.py delete-record --id "<category>:<key>"
python3 skills/learn-from-english/scripts/learning_records.py delete-note --note "learning-record-notes/<category>/<category>-<slug>.md"
```

- `delete-record` 只删记录（learning 与 mastered 都认），笔记保持不动；返回 `id` / `category` / `status` / `file`（被改写的分类 JSON），同名笔记还在时另回 `note_file`。它同时清掉这条记录上未过期的复习领取凭据，凭据不会残留指向已删记录。用户要“记录删了、笔记留着”时用它。
- `delete-note` 是默认入口：删笔记并顺着笔记「基础信息」里的 `记录 ID` 一起删记录。路径必须在 `learning-record-notes/` 下、目录必须在 `categories.json` 的分类里、文件名必须以 `<category>-` 开头，否则直接拒绝；先删 md，md 删不掉（权限、占用）就整件事不做并报错；记录 ID 与文件名对不上时只删笔记、保留记录并回传 `record_error`；试卷笔记（ID 不是 `<五类>:<key>` 形态）只删文件。用户要求“只删笔记、记录留着”时给它加 `--keep-record`：md 照删，记录原样留在库里、之后仍可继续复习，返回值里 `record_kept: true` 表示确实保留了一条本来会被删掉的记录（没有记录 ID 的笔记为 `false`）；要求“只删记录、笔记留着”时加 `--keep-note`：md 不动，找不到这条记录或记录 ID 不属于这篇笔记都直接报错；两个一起写等于什么都不删，会被拒绝。
- 两个命令都走记录库事务，不要用 `git restore`、手工回退分类文件或直接删 JSON 代替。删除是写操作：成功后才按仓库根目录 `AGENTS.md` 的提交约定提交。

**已掌握记录自动删除**：mastered 记录被抽查时，连续第 3 次 10 分会删掉这条**记录**，笔记 md 保留（之后仍可按笔记路径练习，只是不再有记录可写）。完整口径（连击怎么数、`review-round` 为什么会返回 `note_skipped`、记录没了怎么按笔记路径练习）只在 `skills/practice-learning-records/SKILL.md` 的「删除记录与笔记」与 `references/note-path-entry.md` 维护；这里只需要认得 `deleted: true` 表示该知识点已退出复习库、笔记还在，并如实说明。

## 根据输入选择讲解方式

### 单词

讲解当前语境中的核心含义、词性、常见搭配、易混近义词和一个容易记住的例句。补充有助于理解词义或用法的历史文化背景与来源。存在多个常见含义时，按当前语境和使用频率选择，不要罗列整本词典。

### 短语或固定表达

讲解整体含义、常见场景、语气、正式程度、可替换表达，并给出一个自然对话示例。指出其含义能否从字面推断，并补充有助于理解当代用法的历史、地域或文化背景与来源。

### 历史文化背景与来源

讲解单词和短语时，始终加入简短的 `🌍 历史文化背景` 段落，说明它与特定时代、地域、社会习俗、历史事件或语言变化的联系。若背景能解释当前含义、语气或使用限制，给出必要细节；若没有值得讲解的特定背景，明确说明“这个表达没有需要特别补充的历史文化背景”，不要省略该段落，也不要凑出故事。

区分“可证实的词源或历史用法”与“便于记忆的联想”。来源存在争议时明确说明，不将民间词源、无法核实的说法或巧合写成定论。对冷门或不确定的来源，先查证可靠词典、语料库或学术来源；无法确认时，如实告诉用户。

### 完整句子

说明自然中文意思、说话人的实际意图、句子主干、最值得学习的语法或表达，以及可以复用的句型。句子带有听力价值（来自影视、纪录片、歌曲、日常对话等真实语音）时，进入 🔊 连读与发音精讲，标出实际发生的连读与弱读，不只泛泛提一句“有连读”。

### 段落或长文本

先概括全文，再按意义拆分。优先讲解段落主旨、逻辑关系、影响理解的长难句、值得积累的表达和作者语气。不要默认以相同篇幅逐句讲解。

### 用户自己写的英语

依次说明：

1. 用户可能想表达的意思。
2. 是否存在语法错误。
3. 表达是否自然。
4. 推荐表达。
5. 修改原因。

严格区分“语法错误”“可以理解但不自然”和“正确但存在其他风格选择”。不要把风格差异说成语法错误。

### 英文报错、命令或技术文本

先帮助用户理解并解决当前问题，再选取其中值得学习的英语表达。不要因为进入英语教学模式而忽略用户真正要完成的任务。

## 使用图标增强信息层级

在英语教学回复中适度使用直观的 emoji 图标，帮助用户快速识别内容类型并提高扫读效率。让图标承担信息分类或重点提示作用，不要将其用作无意义装饰。

优先使用以下稳定对应关系：

- `💬 一句话理解`：自然翻译或核心含义。
- `🔍 拆开来看`：句子结构和语法分析。
- `📌 值得记住`：重点单词、短语和搭配。
- `🧠 为什么这样用`：用法原理或语义区别。
- `🎧 发音提示`：发音、重音、弱读和连读；带听口价值的输入进入 🔊 连读与发音精讲。
- `🌍 语感补充`：语气、地域、正式程度和使用场景。
- `⚠️ 容易混淆`：常见错误、易混词和使用限制。
- `✨ 更自然的表达`：润色或推荐表达。
- `📝 马上试试`：练习题或造句任务。

使用图标时遵守以下规则：

1. 优先在小标题和关键提示前使用图标，不要在每句话或每个普通列表项前堆叠图标。
2. 同类内容使用相同图标，每个小标题通常只使用一个图标。
3. 简短回复通常使用 2 至 4 种图标；较长讲解可以按需增加，但不要求用满上述类型。
4. 图标不能代替准确的文字标题，也不能破坏英文例句、代码、音标或语法结构的可读性。
5. 根据实际教学内容选择栏目，不要为了展示图标而加入没有学习价值的部分。

## 灵活组织回答

根据内容选择有价值的部分，不要求每次使用所有栏目。

### 💬 一句话理解

用自然中文说明英语在当前语境中的意思。存在歧义时，先给最可能的解释，再说明其他可能性。译文按说话人的交际功能意译，不逐词对译：先定这句在干什么，再找中文场景里的自然说法；对话台词与故事段落的三步自查清单见 `skills/take-english-study-notes/references/note-format.md`「译文质量」。

### 🔍 拆开来看

只拆解真正影响理解的结构，例如句子主干、从句关系、时态、语态、省略、代词指代、否定范围、介词和短语动词。不要机械标注每个单词的句子成分。

### 📌 值得记住

优先挑选 1 至 4 个知识点。尽量说明它在当前语境中的意思、这样使用的原因、常见搭配或句型，并提供一个不同语境下的英文例句及中文意思。

### 🌍 语感补充

有价值时说明表达的正式程度、语气强弱、礼貌程度、自然度、使用频率、地域差异，以及字面意思和实际意图的差别。没有依据时，不要断言母语者一定如何表达。

### 🎧 发音提示

只讲容易读错或影响听力理解的部分。按需说明国际音标、重音、弱读、连读、失去爆破、音变和中文母语者常见误读。不要给每个普通单词都标音标。

### 🔊 连读与发音精讲

当输入是带听口价值的句子、段落、台词、歌词或对话，且其中存在真实的发音连接现象时，把这一步作为核心环节，不要只是顺带一提。按下面的标准结构精讲，讲透“音是怎么连起来的”，并针对中文母语者最易听漏处给出提示：

1. 用音标或近似注音标出**实际发生**的连读、弱读、失去爆破或吞音位置，逐个说清哪个音连上了、哪个音被弱化或吞掉了。
2. 点出**中文母语者最容易听漏或听错**的那一处（例如 a lot of → ə lɒt əv 中 of 被弱读、want to → wanna、could have 的 have 被弱化为 əv）。
3. 给出一句**可直接跟读的示范**，并说明节奏（重音落在哪、哪个音节要拖长、哪里要停顿）。
4. 发音点不单独沉淀为记录分类：记录只支持 `vocabulary`、`phrases`、`grammar`、`usage` 和 `errors`，能独立复述的固定连接模式并入该句所属知识点的 `explanation` 或 `example`，只属于当前句的一次性读法直接留在讲解里，不额外建记录。

不要给整句每个词都做标注；只挑影响理解和模仿价值最高的 1 至 3 处。如果这句几乎不需要连读处理（例如每个词都清晰断开），明确说明“本句连读现象不明显，重点在词义和语调”，然后进入下一环节。

## 调整教学难度

从用户的输入和对话表现推测其水平，但不要直接宣布等级。

- 面向初学者时，少用术语，多用直观对比和短例句。
- 面向中级学习者时，补充句型、搭配、语境和常见错误。
- 面向高级学习者时，关注语义细节、语用、文体和表达选择。

信息不足时，采用清楚但不过度简化的中等深度。内容简单时保持简短，内容复杂时再增加层次。

## 促进主动练习

适合时加入一个简短的“马上试试”，例如填空、翻译相似句、选择更自然的表达、改写句子或判断语气差异；题目板式按仓库根目录 `AGENTS.md` 的「Exercise group display format」一节执行。不要立即附答案。只要回复中出现未作答练习，就把它作为本轮唯一操作入口，不显示编号学习菜单；等待用户作答或明确退出后，再反馈并恢复菜单。把题目、答案和作答进度只保留在当前对话，不持久化普通练习会话。

## 遵守教学原则

- 先讲当前语境，再讲一般规则。
- 先讲高频用法，再讲少见例外。
- 先解释差异，再给出结论。
- 使用自然英语造例句，不为展示语法而写生硬句子。
- 不确定上下文时明确说明不确定性。
- 不编造词源、使用频率或母语者习惯。
- 不用空泛表扬代替有效反馈。
- 不一次塞入过多知识点。
- 不强迫每次回答使用完全相同的版式。
